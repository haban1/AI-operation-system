# ADR 0001：保持运营合同，兼容接入 Traceable RAG 核心策略

- 日期：2026-11-06，Australia/Sydney
- 状态：实施
- 基线：`b8fcff778cc855a0dfb3846e25afed394c1aa5ad`

运营系统的 RAG 是独立服务；外部 Traceable RAG 的接口、索引和知识生命周期不能
直接覆盖运营目录。改地址或仅复制一个 agent 文件，会丢失发布范围、快照或引用合同。

在现有 `rag-service` 中移植有界检索、证据集一致性与回答人设策略，保持
`/rag-api/v1/query`、FastEmbed/Qdrant、不可变文档版本、候选测试、正式发布和回滚。
主程序继续负责平台风险路由、人工状态、会话新旧核验、通知和实际发送；模型不能操作
这些业务状态。没有迁移向量、发布未审核资料或接入微信助手的另一套 RAG。

证据不足和用户意图不明确分别表达；明确提问不因无答案重复计入澄清次数。评论单轮
无可靠答案的人工处理、主动人工请求、风险与已人工接管会话沿用原规则。

人设在知识库范围内持久化，只控制生成语气。它不参与检索、Gate、权限和发布决定。

代价：这是兼容移植，运营运行时仍由本仓库版本管理，不会实时跟随外部 RAG 仓库。
后续共享包化必须先统一独立核心接口和版本合同，不能声称修改一处自动同步全部应用。
