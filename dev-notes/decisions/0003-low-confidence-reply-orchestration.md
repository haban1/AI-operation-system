# ADR 0003：低置信度回复由业务编排层分档处理

- 日期：2026-11-23，Asia/Shanghai
- 状态：实施（分支 `feat/reply-handoff-optimization`，基线 `b5144ff`）
- 替代：[ADR 0001](0001-operations-rag-boundary.md) 中“明确提问不因无答案重复计入澄清次数”一句；其余条款不变。

用户反馈：知识问答在高置信度时可用，低置信度时“人机感”太重——统一回复“这个问题建议向人工客服咨询一下”，
却没有真正通知人工、也不计入引导次数，用户可能反复得到同一句；口语化问题召回不到时尤其明显；
与业务无关的问题也被推给人工。

决定：私信 RAG 返回 NO_ANSWER 时，由 `src/services/reply-composer.js` 分三档组织话术。

1. 有相关候选（标题与“原问 + RAG 改写后的标准问法 + 关键词”至少两个双字词重叠；或一个重叠且 rerank 归一分 ≥ 0.12；
   或候选落在相关档，即归一分 ≥ `RAG_RELATED_MIN_SCORE`，默认 0.25，低于作答门槛 0.38）：
   按相关度用 1–3 个候选标题确认方向，用户回“是”或序号后，以确认后的问题再走一次完整 RAG。
   相关档是口语化问题的主要兜底：“要钱不”和“课程收费标准”字面不重合，但重排分数能反映相关性。
2. 明显无关（天气、股票、娱乐、作业等，且无相关候选）或 RAG 判定 OUT_OF_SCOPE：
   友好划定服务范围，不推给人工，不计入引导次数。
3. 其余知识缺口：积极说明暂时答不准，按问题类型（联系方式、楼层、报名、排期）给出具体说法，
   邀请“转人工”并登记带原问题的待确认人工意图；计入引导次数，但不把计数直接推到上限。

不变的边界：RAG 门槛、证据 Gate、引用校验、人设范围都不改；候选只用于确认方向，
永不陈述为事实、永不作为 sourceReferences；评论渠道、小程序转人工状态机、微信助手话术沿用原规则。

取舍：放弃“检索失败绝不回问”的旧约束，换取低分但相关时能贴合用户问题。风险是候选与用户意图不符时多一轮确认；
用户否认后不再提同一候选，同一方向也不在相邻轮次重复。无关词表只在 RAG 已无答案后生效，误判代价只是换一种说法。

后果：知识缺口现在会累计到 `BUSINESS_GUIDANCE_MAX_ATTEMPTS`；累计达到上限后，前置的“缺对象”澄清会按既有规则转人工。
转人工时给用户发回执、运营接管/交还 AI 需要改动发送状态机，留到后续 P1。
