# YYYY-MM-DD：任务主题

日期：YYYY-MM-DD（Asia/Shanghai）
状态：填写实际阶段，例如已实现待提交；不要将计划写成结果。
关联：填写需求/issue/PR（若有）、分支、已知基线提交；本提交哈希在提交后由 Git 查询。

## 背景与目标

填写触发问题、必要背景、用户已确认约束及可判断是否完成的目标。

## 变更与影响

填写前后行为、涉及模块/文件和受影响用户或接口。链接权威主题文档，避免重复维护。

## 决策与取舍

填写选择及理由、影响后续工作的备选方案；无重要取舍时说明原因。架构决策可链接 ADR。

## 验证与证据

填写实际执行的命令、环境、结果和证据位置；失败、未执行和无法覆盖的范围分别说明。不要粘贴秘密或原始业务数据。

## 部署与回退

填写配置、迁移、兼容性和回退方法；无运行影响时明确说明。

## 未完成与下一步

填写剩余工作、阻塞和下一条可执行行动；已完成时说明下一接手者要核验什么。明确哪些动作仍需授权。

## 上下文与关联

填写接手入口、关键约束、相关代码/文档、后续定位命令；从干净克隆能找到这些信息。
