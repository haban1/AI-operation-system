# 04 B站平台闭环流程

## 1. 范围与职责边界

本流程覆盖 B站内容发布、评论通知采集与精确回复、私信会话采集与精确回复。

- 回复文案由现有知识库、策略和决策任务生成。
- B站适配器只负责安全采集、精确目标绑定、发送、平台回执校验和停止态保护，不在适配器内生成回复文案。
- 不修改公共基类、注册表、Web、数据库或其他平台实现。
- 现场真实发布和回复必须由主任务按平台编号排队执行；本任务仅做无浏览器自动化测试。

## 2. 内容发布闭环

1. 在获取页面前执行运行态检查；平台已停止或生命周期已变化时立即阻断，不打开浏览器/Profile。
2. 预检视频文件、扩展名和内容来源；不符合要求时不进入上传。
3. 检查已有未提交草稿：发现冲突时保留草稿，不点击继续编辑或放弃，也不重复上传。
4. 调用现有草稿准备流程填写视频、标题、简介等页面字段。
5. 设置自制/原创声明；AI 内容必须同时设置 AI 声明。声明无法确认时停留在草稿态。
6. AUTO 发布必须获得 `managementConfirmed === true`，并且只允许点击唯一、可见、可用的最终投稿按钮。
7. 点击后仅在平台成功信号明确出现时返回 `SUCCESS`。
8. 上传或最终提交已经发生但结果不确定时返回 `NEEDS_CONFIRMATION`，禁止对非幂等发布进行盲目重试。

## 3. 评论通知与精确回复

1. 从 B站评论通知 API `/x/msgfeed/reply` 读取评论事件。
2. 优先使用通知 ID 作为稳定外部 ID；缺少通知 ID 时使用 `oid:sourceReplyId` 形成稳定 ID。
3. 采集并保存精确回复目标：`oid`、`type`、`root`、`parent`、`sourceReplyId`、`targetReplyId` 和评论者 `mid`。
4. 发送前要求有效 CSRF 和正整数目标 ID，调用 `/x/v2/reply/add`。
5. 只有 API 明确成功且返回评论 `rpid` 时返回 `SUCCESS`，并将 `rpid` 作为平台消息 ID 回执。
6. API 明确拒绝返回 `FAILED`；请求已发送但网络或响应不确定时返回 `NEEDS_CONFIRMATION`，不自动重试。
7. 当前评论人工回复检测不伪造成功，无法可靠确认时保持 `NEEDS_CONFIRMATION`。

## 4. 私信会话与精确回复

1. 先读取私信会话列表，再按未读会话读取消息；每个会话读取前重新检查平台运行态。
2. 只采集对方发送、未读、有有效 `msg_key` 的文本消息，并绑定 `talkerId`、`msgSeqno`、时间戳和当前账号 `selfUid`。
3. 使用 `bili-private:<msg_key>` 作为稳定外部 ID，避免重复采集。
4. 发送前要求有效 CSRF、正整数 `talkerId/selfUid`，调用 `/web_im/v1/web_im/send_msg`。
5. 只有 API 明确成功且返回新的 `msg_key` 时返回 `SUCCESS`，并将其作为平台消息 ID 回执。
6. API 明确拒绝返回 `FAILED`；发送结果不确定时返回 `NEEDS_CONFIRMATION`，禁止盲目重试。
7. 人工回复检测要求发送者为当前账号、接收者为目标会话、文本完全匹配、消息位于源消息之后，并取得有效 `msg_key`。

## 5. 停止与安全语义

- 页面获取、登录检查、API 访问、上传、采集、发送前后均通过运行态检查保护。
- 初始停止态必须在 `getPage` 前阻断，因此不会启动浏览器或打开 Profile。
- 停止后不再开始新的采集、发布或回复动作。
- 非幂等请求尚未发送时可直接阻断；已经尝试发送或提交后遇到停止/异常时返回 `NEEDS_CONFIRMATION`，避免重复发布或重复回复。

## 6. 主任务现场排队验收（编号 04）

1. 使用已登录测试账号只读复核评论通知、私信会话和消息 API 的最新字段结构。
2. 复核存在未提交草稿时不会重复上传或覆盖草稿。
3. 使用测试素材验证分区、封面、声明、最终投稿按钮和成功页/管理页信号。
4. 使用测试评论验证 `oid/type/root/parent` 精确回复及 `rpid` 回执。
5. 使用测试私信验证 `talkerId/selfUid` 精确发送及 `msg_key` 回执。
6. 在每个阶段切换平台停止态，确认不会新开浏览器、不会继续领取或发起新操作。

## 7. 尚存风险与公共钩子

- B站 Web API、DOM、按钮文案和成功页路径可能变化，需现场按编号复核。
- 评论采集当前主要依赖通知 API 首屏结果，深分页策略需由主任务结合公共调度频率评估。
- 私信默认最多扫描 30 个未读会话，可配置但单次上限为 50。
- 评论人工回复目前缺少可靠的公共只读确认钩子，因此不会将不确定结果误报为成功。
- 分区、封面及账号差异导致的必填项仍依赖现有公共 `prepareDraft` 页面流程，需现场验证。
