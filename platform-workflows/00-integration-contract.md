# 五平台闭环开发：总控与验收约定

## 目标
在现有平台运行开关、任务 claim、Local Agent 和知识库决策框架内，分别打通微博、抖音、视频号、B站的内容发布、评论采集与知识库自主回复、私信采集与知识库自主回复。

## 代码隔离
- 01 微博：仅修改 `agent/rpa-adapters/weibo-assisted.js` 及其独立测试/流程文档。
- 02 抖音：仅修改 `agent/rpa-adapters/douyin-assisted.js` 及其独立测试/流程文档。
- 03 视频号：仅修改 `agent/rpa-adapters/wechat-channels-assisted.js` 及其独立测试/流程文档。
- 04 B站：仅修改 `agent/rpa-adapters/bilibili-assisted.js` 及其独立测试/流程文档。
- 公共基类、Registry、Web、数据库和 package 脚本由总控任务统一修改，避免并行冲突。

## 硬性安全标准
1. 平台或全局停止时不得打开浏览器/Profile、不得检查登录、不得采集、不得 claim 或执行任务。
2. 回复必须精确定位当前目标，并核对稳定 ID、用户、正文和必要的时间/会话证据。
3. 不得把历史消息、列表预览、多目标或不确定目标当作可自动回复对象。
4. 发布只有取得本次平台提交回执才能返回 SUBMITTED/SUCCESS，页面提示文字不得冒充成功。
5. 非幂等动作发生不确定结果时进入 NEEDS_CONFIRMATION，不得盲目重试。
6. 自动回复文案继续由现有知识库、决策、风控和任务系统生成；适配器只负责安全采集、定位、发送和回执核验。

## 现场调试排队
同一时间只允许运行一个平台：
1. 微博
2. 抖音
3. 视频号
4. B站

每个平台调试结束后必须关闭平台并确认 Chrome/Profile 已释放，下一平台才可开始。

## 总验收
- 平台专属自动化测试全部通过。
- 项目全量测试通过。
- 五个平台分别验证发布准备、评论采集/回复准备、私信采集/回复准备。
- 停止态入口返回阻断，浏览器数量不增长。
- 一个平台注册/停止/执行不会调用另一个平台适配器。
