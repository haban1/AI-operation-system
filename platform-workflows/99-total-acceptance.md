# 四平台总验收报告（2026-08-07）

## 验收范围

- 微博、抖音、视频号、B站独立适配器。
- 内容发布。
- 评论采集、知识库决策后的精确回复执行。
- 私信采集、知识库决策后的精确回复执行。
- 平台停止态硬阻断、平台实例隔离和非幂等安全语义。

## 实现结论

1. 四个平台均使用独立适配器和独立浏览器 Profile，不共享平台实例。
2. 发布、评论、私信入口均在浏览器打开前和最终非幂等动作前检查平台运行状态。
3. 评论和私信必须按稳定 ID、用户、正文、会话或作品上下文进行唯一匹配；不确定目标不会自动发送。
4. 发布和回复只有取得本次操作的可靠平台回执才返回成功；点击后回执不确定统一进入 `NEEDS_CONFIRMATION`，并标记为不可盲目重试。
5. 知识库、风险判断和回复文案仍由 Web 现有闭环负责，平台适配器不绕过知识库自行生成回复。
6. 调试队列默认拒绝选择存在排队任务的平台，防止调试时反向唤醒旧任务。

## 尚存风险

1. 本次没有对真实用户执行发布、评论回复或私信回复，避免在缺少明确测试素材、目标消息和授权的情况下产生外部副作用；真实发送仍需使用测试账号和指定目标逐平台验收。
2. 平台 DOM、接口和风控弹窗会变化；选择器和 API 回执需要持续维护。
3. 微博和 B站现有自动采集排队任务在平台和全局同时开启后会恢复领取，实机调试前必须先核对这两个任务。
4. 视频号仍通过公共基类中沿用的抖音命名评论钩子接入，功能已测试，但后续可在单独重构任务中改为通用命名。
5. 网络超时发生在非幂等点击之后时，系统会保守进入人工确认，可能增加人工核对量，但不会自动重复发送。
