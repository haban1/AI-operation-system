# 微信助手系统内集成（2026-11-05）

登录天河后，点击「微信客服」即可直接使用微信助手操作面板。页面自动选择已有机器人，提供联系人、人工接待、好友群发、群聊、知识库及现有管理功能；有多个机器人时可以切换。系统内入口不再要求填写机器人后台登录密钥，也不需要另开 8080 页面。

## 连接状态与聊天入口

账号栏显示“微信在线 / 微信离线”，账号列表及详情每30秒刷新。这个状态表示微信会话状态，容器运行不代表微信已登录；空接待列表也不代表没有收到好友消息。

“人工接待”仅显示已由人工接管的会话。普通好友对话从“联系人 → 好友 → 聊天记录”查看，无需为了看聊天而主动接管、暂停AI。登录问题从“账号操作”或“账号管理”处理。

本轮收发核查、状态展示及验证限制见[微信收信与连接状态记录](changes/2026-11-12-wechat-reception-status.md)。

## 人工接待窗口回复

收到转人工通知后，在“微信客服 → 人工接待”选择客户，即可在右侧输入文字、添加或粘贴图片，点击“发送”连续沟通。Enter发送、Shift+Enter换行；上方最近50条记录每3秒更新，图片可以预览，更早消息从“历史记录”打开。

人工接待期间AI继续暂停，发送消息不会自动恢复AI；结束后点击“恢复 AI 回复”并确认。群聊接待明确标注群聊，回复发到原群，不自动@该成员。微信离线时只能看记录，重新登录后再发送。

各会话草稿在当前页面内分别保留，刷新或离开模块不保留。发送期间禁止切换会话、搜索及恢复AI；失败时保留未确认内容，请先核对记录再重发。文字成功而图片失败时，只重发保留的图片。实现、模拟验证、部署及回退见[窗口回复记录](changes/2026-11-12-wechat-reception-reply.md)。

## 接入方式

天河的 `/wechat-workbench/` 是同源访问入口。HTML、静态文件、管理 API 和媒体下载都经过天河管理员会话验证。服务端使用原机器人后台的登录密钥建立机器人会话，机器人 Cookie 只保存在服务端，浏览器只持有天河登录 Cookie。退出天河后，该入口随即失效。

机器人后台仍执行原有归属权限检查；微信消息处理、接待状态、群发任务和知识数据继续由现有原生服务负责。独立 8080 入口保留其原有登录方式。天河五平台总开关仍不控制微信服务。

系统内嵌模式隐藏独立站点的登录、退出、访问凭据及宣传外壳。`/user/self`、`/system-settings` 响应中的用户 API Token 不向内嵌页面返回，登录和 Token 刷新接口也不经由此入口开放。

## 配置与部署

在 project 目录执行：

```powershell
node scripts/configure-wechat-workbench.mjs
```

脚本读取正在运行的 `wechat-robot-admin-backend` 容器中的既有 `LOGIN_TOKEN`，生成被 Git 忽略的 `.env.wechat-workbench`，不输出密钥。这个文件仅包含供天河服务端使用的 `WECHAT_ROBOT_ADMIN_LOGIN_TOKEN`。机器人原登录密钥变更后，应重新执行脚本并重建 Web 容器。

`compose.wechat.yaml` 为 Web 配置 `WECHAT_ROBOT_ADMIN_INTERNAL_URL=http://wechat-nginx`，并加载 `.env.wechat-workbench`。机器人部署在其他网络时，修改内部地址并保证天河可访问它；系统内页面不依赖浏览器直连 8080，也不依赖 `WECHAT_ROBOT_ADMIN_FOLLOW_HOST`。

当前本机同时使用微信及内容工作台配置，更新 Web 时保留三个 Compose 文件：

```powershell
docker compose -f compose.yaml -f compose.wechat.yaml -f compose.workbench.yaml up -d --no-deps web
```

Web 的环境变量发生变化需要 `up -d` 重建，单纯 `restart` 不会加载新变量。修改 Node 源码后可重启 Web；修改机器人前端源码后，需要重新构建并更新 `robot-ui` 镜像。无需重启机器人客户端或微信协议服务。

没有配置内部地址或登录密钥时，微信客服页会提示管理员完成接入；上游暂时不可用或天河会话过期时，页面显示错误并允许重新加载。恢复服务端会话不会自动重放发送、群发等写操作。
