# 知识库文件管理

当前入口为侧栏“知识库”，有“文件管理”（`#documents`）、“回答风格 / 人设”（`#answer-style`）和“RAG 问答测试”（`#reply-test`）三个栏目。

## 操作

- 上传：选择或拖入一个文件，点击“上传文件”。最大 50MB；支持 PDF、DOCX、XLSX、TXT、Markdown、CSV、TSV、JSON、JSONL。
- 查询：按文件名搜索，点击“查看”读取解析后的内容。
- 修改：点击对应文件的“修改”，选择修改后的文件并保存。沿用该文件的身份，不新增第二条列表记录；文件名随替换文件更新。
- 删除：点击“删除”并确认。成功后从列表与当前问答检索范围中移除。

上传或修改后自动解析、建立索引并生效。处理期间显示状态并暂缓再次修改/删除；失败显示错误，可修改后重新上传。替换失败时，旧的可用内容继续承担问答。文件选择、编辑中的输入不会被后台状态刷新覆盖。

测试审核、手动发布、版本回退、相似问法管理和自定义转人工说法仍已移除。旧版本/问法/说法书签返回文件列表；`#xiaozhi` 打开新的 RAG 问答测试。正常渠道问答、证据检查、登录认证和内置转人工处理继续存在。

## 回答风格与本地测试

“回答风格 / 人设”可保存助手名称、公司/组织名称、人设与表达要求、问候语。保存后从下一次正式或测试问答生效，不必重新索引或发布；可撤销未保存修改。人设只影响表达，不能改变证据判断或将无依据内容当成事实。已有有效人设配置会重新加载；损坏配置回到默认值。保存失败保留编辑输入。

“RAG 问答测试”直接查询当前生效的文件，使用相同的人设、检索、重排、证据检查和生成流程。选择抖音、微博、B站或视频号作为来源场景；私信保留最近三轮完整问答（最多六条、12000 字），评论单轮。每个问题最多 4000 字，回答上限 600 字。此入口测试 RAG 本身，不模拟平台发送、外层问候/风险路由、账号策略或通知。可查看回答、引用来源、无可靠答案的原因、耗时和追踪 ID。

切换场景或清空对话会开始新测试会话；清空、切页时忽略旧请求结果。对话只存在当前浏览器内存，退出登录会清空，刷新页面不保留；RAG 服务保留既有脱敏追踪。测试不写入业务消息、会话、平台任务、小程序处理任务或通知，也不创建旧审核/发布会话。保存人设会影响正式 RAG 问答，测试提问本身不会发送到真实平台。

## 接口与实现

Web 管理接口：

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/rag/files` | 文件列表、处理状态 |
| `POST /api/rag/files` | 上传文件，异步处理并自动生效 |
| `PUT /api/rag/files/{id}` | 替换对应文件，异步处理并自动生效 |
| `GET /api/rag/files/{id}/chunks` | 查看当前文件解析内容 |
| `DELETE /api/rag/files/{id}` | 移除文件与当前检索引用 |
| `GET/PUT /api/rag/answer-profile` | 读取/保存固定知识库的人设配置 |
| `POST /api/rag/test-query` | 本地测试当前知识，返回 `response` 与 `mode: LOCAL_TEST` |

上传和修改使用 JSON 字段 `filename`、`mimeType`、`contentBase64`。Web 服务固定知识库与操作人，不接受客户端越权指定其他知识范围。RAG 服务对应 `/rag-admin-api/v1/files`，上传/修改使用 multipart；操作仍使用既有服务认证。

人设接口仅接受 `assistantName`（1–60 字）、`companyName`（1–80）、`stylePrompt`（0–4000）、`greeting`（1–240），额外字段拒绝。RAG 对应 `/rag-admin-api/v1/knowledge-bases/{id}/answer-profile`，按知识库持久化在 `service_meta`。Web 固定当前业务知识库并复用管理员认证。

测试请求 JSON：`text`、`sessionId`（可选，最多 80 位字母/数字/下划线/连字符）、`platform`、`channelType`、`context`（USER/ASSISTANT 成对历史）。服务端构造 `LOCAL_TEST` 命名空间、独立请求/追踪 ID、固定知识范围和强制证据约束，再调用 `/rag-api/v1/query`，校验返回快照。客户端不能选择旧索引或放开证据要求；错误保留上游状态码。

公司介绍与业务咨询支持“你们是什么公司”“你们主要做什么业务”等日常问法。只有当前已生效资料的冻结标题范围明确指向唯一机构时，才用该名称补全检索指代；同一中文名称及其紧接的 ASCII 品牌前缀可在有独立标题依据时归一。标题和回答人设不提供业务事实，答案仍来自正文并核验引用；明确其他机构、多个机构或已确定会话对象时，不擅自替换。该补全保留问题中的数字和限制，不降低证据门槛。修复和验证见 [公司指代检索记录](changes/2026-11-11-company-reference.md)。

关键实现：`public/knowledge-files.js`、`src/services/rag-client.js`、`rag-service/app/file_api.py`、`rag-service/app/file_manager.py`。自动热点成片与素材知识草稿确认后的入库也调用文件接口，不再创建测试会话或发布任务。

内部保留不可变检索快照和原子切换，以避免查询读到一半更新的索引；没有运营版本发布或回退 API。每次文件保存只替换该文件的索引成员，保留其他有效文件。修改与删除串行处理，数据库同时校验基础快照，索引失败不切换有效内容。重启可恢复处理中或已解析但尚未生效的文件。

删除采用内部墓碑并原子切换有效索引。历史源文件与快照仍保留用于正在进行的读取和维护备份，不向文件列表、文件读取或正式检索暴露；这不是物理擦除接口。旧小智审核数据保留在既有数据库中，不再创建、修改或控制正式答复。
