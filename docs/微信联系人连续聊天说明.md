# 联系人连续聊天

2026-10-23 已部署到本机微信机器人管理后台。刷新天河页面后，进入微信模块的「联系人」，点击联系人右侧的「聊天」。

## 操作

- 左侧列出联系人和群聊，可搜索、翻页并切换会话，显示头像和名称。
- 右侧显示最近 50 条消息，每 3 秒自动更新。消息按时间顺序从上往下显示，自己发送的消息位于右侧。更早的消息可从「历史记录」进入查询。
- 底部输入框持续保留：Enter 发送，Shift + Enter 换行；发送成功后清空已发送内容并继续输入。
- 支持选择或粘贴图片，发送前可预览、移除。每次可选一张，不超过 50 MB，支持 JPG、PNG、GIF、WebP。同时输入文字和选择图片时，先发送文字，再发送图片。
- 当前聊天窗口内切换联系人会分别保留文字和图片草稿；关闭窗口或刷新页面后草稿不保留。
- 发送过程中锁定联系人切换、关闭窗口和输入操作，防止接收人错位及重复发送。空白消息、已删除或已不可用联系人不能发送。
- 发送结果未确认时保留未确认的内容，由用户核对记录后决定是否重发。若文字成功但图片失败，只保留图片，不重复发送已经成功的文字。
- 向上查看消息时，自动更新不强制跳到底部；有新消息时可点击提示回到最新消息。

## 实现

前端新增 `src/chat/conversation/`，复用现有消息和图片显示组件、生成的文字/图片发送 API 及聊天历史 API。原有聊天记录查询和更多发送方式入口继续可用。

管理后台修正了图片接口的两处问题：从已校验的机器人实例读取 query 中的 ID，兼容接口文档规定的图片表单；检查客户端的 HTTP 状态和业务返回值，避免底层失败仍提示成功。图片发送不自动重试。

聊天历史代理原来固定返回 20 条，现按请求的分页大小读取，默认 20 条、最多 100 条；新聊天窗口请求 50 条。

## 验证与部署

- 前端 `pnpm lint`、TypeScript 检查、生产构建通过。
- 管理后台 `go test ./service ./controller -run '^TestConversation' -count=1` 通过，覆盖图片请求参数、成功/失败/无效响应、不会重复请求及历史分页。
- 隔离页面测试覆盖：连续发送、不同好友和群聊、草稿隔离、快速切换、自动更新、文字换行、空消息限制、双击防重复、图片预览和发送、文字成功图片失败后的独立重试、跨页搜索、不可用联系人禁发。
- 所有发送测试均使用模拟服务，没有向真实微信联系人发送消息。部署后只读检查真实联系人与聊天历史接口、已构建前端文件和微信在线状态。
