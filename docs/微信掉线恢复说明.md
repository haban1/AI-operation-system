# 微信掉线恢复

2026-10-23 修复机器人客户端收到掉线通知后，误关闭协议服务自动心跳的问题。

## 运行行为

- 协议服务负责心跳、长连接和自动二次登录；客户端不再另起登录重试循环。
- 掉线回调只标记离线、暂停后台任务，保留协议服务已有的重试。
- 客户端每 30 秒检查登录状态，即使后台页面未打开也会运行。连续三次检查失败才因探测结果标记离线；协议明确发来的掉线回调立即生效。
- 单次资料查询最多 12 秒，整次状态检查最多 15 秒；HTTP 错误、空资料、账号不匹配和协议错误都不能判为在线。
- 登录恢复后重新启用自动心跳、同步管理后台状态并恢复既有任务。连续成功的检查不重复创建任务。
- 主动退出会关闭协议心跳并退出微信。退出意图存入该机器人 Redis 库的 `robot:session:manual_logout:<机器人ID>`，重启客户端也不会自动恢复；重新登录成功后清除此标记。
- 更新或重启客户端只停止本地检查器，不关闭仍在协议服务中运行的心跳。

本次修复解决客户端中断重试的问题。微信端明确使登录凭据失效、且协议服务无法自动恢复时，仍需要重新扫码。不能保证账号永不掉线。

## 验证

在 `wechat-assistant/wechat-robot-client` 中执行：

```sh
go test -race ./pkg/session
go test ./pkg/robot -run 'TestLoginProbe' -count=1
go test ./service ./startup -run '^$'
CGO_ENABLED=0 go build -trimpath -o .build/wechat-robot-client .
```

上述测试使用模拟依赖和本地 HTTP 服务，不向微信发送消息。不要直接运行整个 `pkg/robot` 测试包：其中保留了上游连接外部微信服务的测试。

## 本机更新与回退

运行配置为项目根目录的 `compose.robot.yaml`，使用 `.env.robot-native` 和 `.env.robot-client`。只更新 `robot-client`，无需重启协议服务或数据库。

本次修复镜像为 `tianhe-wechat-client:session-recovery-20261023`，同时更新 `tianhe-wechat-client:native`。旧镜像保留为 `tianhe-wechat-client:before-session-recovery-20261023`；源码与部署检查记录保存在忽略提交的 `backups/wechat-recovery-20261023/`。

需要回退时，在项目根目录执行：

```sh
docker image tag tianhe-wechat-client:before-session-recovery-20261023 tianhe-wechat-client:native
docker compose --env-file .env.robot-native -f compose.robot.yaml up -d --no-deps --no-build robot-client
```

回退会重新引入本次修复的掉线重试缺陷，仅用于故障处理。
