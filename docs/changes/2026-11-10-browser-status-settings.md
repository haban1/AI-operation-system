# 浏览器状态与修复帮助

## 背景与目标

原“浏览器控制”放在平台账号中，默认展示大量执行体系和技术说明。用户要求收进系统设置，让普通使用者能看懂状态并找到修复方法。

## 变更与影响

入口调整为“系统设置 → 浏览器状态”，保留 `#browser` 和 `#browser-tools` 书签。默认只显示各账号的状态、检查时间、刷新和帮助按钮；修复弹窗按连接、登录、验证、暂停等情况提供步骤及原页面入口。原命令表单、设备/浏览器信息、会话复制和检查记录仍可在“维护详情”展开使用。

涉及 `public/app.js`、`public/browser-status.js`、`public/workspace.css`、`public/index.html` 及导航测试辅助和专项测试；后端、接口、配置、依赖和业务任务规则不变。

## 决策与取舍

- 可选控制台未启用不等于故障；主动暂停、平台停止和账号停用用中性状态。
- 即时执行端连接与账号绑定结合使用；平台浏览器运行时只信任账号所属设备二十秒内的心跳，忽略历史启动时间、任意其他设备和历史诊断成功记录。
- 登录状态只有来自 Local Agent、且检查时间在过去十五分钟内时才用于正常/登录/验证判定，否则显示待检查并保留上次检查时间。正常表述为“最近检查正常”，避免把历史结果扩大为本轮业务验收。
- 同平台多个启用账号分别显示，避免只检查第一个账号。沿用五秒 bootstrap 轮询，只替换变化的状态面板，保留维护表单输入；打开修复弹窗或手动刷新时暂缓面板替换。
- 当前没有安全重启浏览器的现成 HTTP 接口，因此提供实际修复步骤和原有登录入口，不添加虚假的“一键修复”，不自动重试发布或回复。
