# 2026-11-12：内容创作成片库流程统一

日期：2026-11-12（Australia/Sydney）。基线 `304f707`（main）。状态：已在本机 3101 验证，用户要求推送到 main；未部署。

## 背景与目标

用户指出热点页的“成片库”页签多余，希望流程统一为：混剪或 AI 热点产出的成片，手动确认后进入成片库，再到“发布管理”使用。同时要求整体梳理内容 Tab 的操作逻辑，让调用链路更顺、页面更简洁，并参考最佳实践。

## 现状核对

后端已经是这条链路：成片（混剪导出、热点成片）进入共享内容库时为待确认（`admissionStatus: pending`），调用 `/api/studio/outputs/confirm` 后变为已批准，发布管理的选择器只把已批准的成片用于发布。问题出在界面：

- 同一状态有多种叫法：“可发布 / 确认可发布 / 确认并用于发布 / 素材库 / 成片与素材”。
- 入口重复：热点页自带“成片库”页签，并另有一套热点成片页。
- 混剪导出完成后只能下载，要回到另一个页面才能确认入库。
- 热点页的“成片详情”页签在没有打开成片时是空页面。

## 设计依据

- Nielsen 可用性原则：一致性与标准（同一对象一个名称、一个状态词）、系统状态可见（状态数量直接显示）、识别优于回忆（下一步按钮放在产出位置）。
- Hick 定律：减少同级选项与重复入口。
- 渐进披露：只在需要时出现的功能（如成片详情）不常驻。
- 统一的收件箱式审核：待处理 → 处理后归档，参照 Gmail、Linear 的 Inbox 分段计数。

## 变更与影响

- **统一命名**：顶栏“成片与素材”改为“成片库”；状态统一为“待确认 / 已入库”；按钮统一为“确认入库”（单条和批量）、“入库并去发布”（预览及发布选择器中的待确认成片）、“去发布”（已入库）；空状态与提示文案同步修改。发布管理按钮及弹窗由“从素材库选择”改为“从成片库选择”。
- **成片库页**（`engines/video-studio/dist`）：
  - 状态下拉框改为分段切换“全部 / 待确认 / 已入库”，并显示数量；原下拉框保留为取值来源。
  - 统计行精简为“共 N 条”。
  - 在成片库视图中隐藏旧的“使用工作流”入口；发布选择器（picker）中的行为不变。
- **混剪导出后直接入库**：导出完成面板中，“加入成片库”成为主按钮，“下载成片”为次按钮。点击后由外层工作台对 `montage-<jobId>` 调用原确认接口，结果回传：成功显示“已加入成片库 ✓”；成片尚未同步时提示稍后到成片库确认。
- **AI 热点**：
  - 去掉“成片库”页签；“成片详情”只在打开某条成片时显示。
  - 成片对比的保存按钮改为“保存所选版本，去成片库确认”；保存后进入成片库，并筛选为“自动热点 · 待确认”。
  - “打开成片库”改为“去成片库确认”。
  - 页面说明改为“勾选满意的版本，保存后到成片库确认入库；不满意可填写反馈重做”。
- 测试 `test/montage-workbench.test.js` 中断言的顶栏文字由“成片与素材”改为“成片库”。

后端接口与确认、发布逻辑未改动。

## 决策与取舍

- 仍保留“待确认”这一步，不自动入库：发布前需要人工确认，这是既有的人工确认边界。
- 热点的多版本对比需要先选版本，因此热点的入库仍在成片库中统一确认，没有从对比页直接调用确认接口；对比页的运行记录与库内成片之间暂时没有可靠的 ID 对应关系。
- 混剪导出可以直接入库，因为 `montage-<jobId>` 与库内成片 ID 一一对应。
