# 知识库精简为文件增删改查

## 背景与目标

用户要求知识库仅保留上传和每份文件的增删改查，删除截图中的版本、相似问法、回答风格、转人工说法、测试等栏目；随后明确小智内容及相关后端逻辑也要移除，不能只隐藏页面。

## 变更与影响

- 新文件管理页面只有上传、搜索、查看、替换文件和删除；处理完成自动生效。删除版本摘要、AI 草稿列表、测试/发布操作和对应栏目，旧栏目书签回到文件列表。
- 新增 Web/RAG 文件 CRUD API，复用解析、分块、向量检索与证据生成。删除小智服务、审核决策服务、测试会话/答案审核、手动发布/回退、旧文档管理、问法/风格/自定义转人工说法等管理路由与后台任务入口。
- 删除旧的问法生成/知识表格导入服务和对应生成函数；保留旧正式答复兼容路径需要的基础文本归一化。正式问答不再受小智禁用记录控制；使用固定默认回答表达，转人工继续识别内置明确指令。
- 自动热点内容及素材草稿入库改为直接保存文件，等待文件生效，不再测试或发布。旧 RAG 控制台静态页面和测试/评测管理 API 也移除。

接口、数据生命周期、失败行为与操作说明集中在 [知识库文件管理](../knowledge-files.md)，技术边界见 `rag-service/ARCHITECTURE.md`。

## 决策与取舍

保留内部不可变索引快照，但删除人工测试、发布和回退工作流。它只用于原子切换、并发与运行中查询的一致性，不在产品中提供版本操作。替换保留文件 ID；只有新内容处理成功后才替换生效内容。删除通过原子切换移出检索并写墓碑，历史源文件/索引与旧数据库表不做破坏性清理，不能当作物理擦除承诺。

登录认证、RAG 服务间认证、证据不足拒答和必要的人工接管属于正常消息处理，不以“去掉权限”为由移除系统登录或放开跨库访问。原渠道配置、平台账号、消息与会话数据保持。

## 部署与回退

已应用当前开发目录的前后端文件，使用既有 bind mount，重启 `tianhe-dev-rag-1` 与 `tianhe-dev-web-1`，其他业务容器未重建。既有有效知识无需重新导入或重新发布。私有源码备份、两份数据库在线备份、资源指纹和 UI 截图位于 `.codex-work/knowledge-files-20261110/`，不得上传。

维护回退时依据本轮清单、起始备份与当前差异逐段撤销知识库改动，并删除仅由本轮新增的模块，再重启这两个服务；普通界面没有回退入口。`public/app.js`、`public/index.html`、展示模块及交接文档同时包含发布步骤等其他任务的修改，禁止整文件覆盖；清单中的哈希用于核对快照，不代表整份差异都归本轮所有。若本轮之后有真实文件操作，先评估其索引/墓碑，不能直接覆盖新业务数据或回退整个脏工作树。原始数据库备份仅供必要的人工恢复，不自动导入。
