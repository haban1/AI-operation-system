# 公司介绍与业务咨询的指代检索修复

## 背景与目标

公司资料已解析并生效，但“你们是什么公司”“介绍一下你们公司”等常用问法仍返回证据不足；完整机构名称提问可正常回答。本轮修复查询标准化和机构名称校验，让现有资料可通过日常问法检索，不要求运营重新上传原件。

## 变更与影响

- `rag-service/app/query_rewrite.py`：机构后缀匹配在第一个完整机构处停止，排除疑问句、介绍措辞及日期金额约束的误识别；只在同一已冻结标题范围独立出现相同中文名称时，将其紧接的 ASCII 品牌前缀归为一个检索名称。
- 当当前已冻结资料标题明确指向唯一机构，且用户询问公司介绍或业务、当前问题及已补全上下文中没有明确的其他机构时，以校验过的机构名替换“你们/贵公司”等检索指代；连续追问中沿用同一历史指代时亦适用。其他文字、数字、否定和限制条件保留。该步骤不依赖改写模型返回 JSON，也不读取表达性人设作为事实。
- `rag-service/app/pipeline.py`：召回与重排使用相同的检索指代结果；保留原问题用于证据审核和答案生成，原证据门槛、引用核验、两轮检索预算和资料范围不变。改写模型不可用时也能读取冻结范围的标题，仍不跨知识库或版本。
- 新增 `rag-service/tests/test_company_reference.py` 的隔离测试；操作说明见 [知识库文件管理](../knowledge-files.md)。未修改 PDF、知识正文、业务开关、模型或人设。

## 决策与取舍

不通过降低证据门槛、硬编码业务答案、改写原件或让人设代替证据解决问题。标题仅提供检索对象，不证明助手身份或业务事实；回答仍必须得到已生效正文和有效引用支持。多个不同中文机构、明确另一机构、非公司意图及不明确的第三方指代继续走现有检索流程。

名称归一仅覆盖“相同中文名称及紧接的 ASCII 前缀”这一有明确标题依据的情况，不将地域不同、中文前缀不同或仅有相似后缀的公司自动合并，也不实现通用机构实体识别。完整上下文已补全对象时优先使用现有会话处理。

证据流程中另一个旧用例要求诊断值 `reject`，现代码返回 `retry`，在修复前的文件副本上单独复现相同失败，未改动该既有行为。旧 `test_query_rewrite_flow.py` 引用已移除的 `DebugQueryRequest`，无法在当前接口收集；本轮未为该历史接口补兼容层。不能宣称全套历史测试通过。
