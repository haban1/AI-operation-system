# 2026-11-12：评论与私信来新消息时原位更新

日期：2026-11-12。基线 `8b92b6d`（main）。状态：已修改，本地验证通过；未提交、未推送、未部署。

## 背景与目标

[后台刷新防闪烁](2026-11-12-dashboard-refresh-flicker.md)已覆盖运营总览和平台账号页。复测发现评论/私信页在数据没变化时稳定，但每采集到新评论或私信，`renderMessages` 仍会整页重画：先清空 `#content`，再重新整理成收件箱，用户会看到一次闪动。目标是新消息到达时只更新变化的部分，保留展开的帖子、选中的评论或会话、筛选和搜索。

## 变更与影响

- `public/app.js`
  - `renderMessages(data, { background: true })`：定时刷新发现数据签名变化时，在离屏节点渲染整页、执行同样的展示层整理（`applyInteractionPresentation`），再用 `patchBackgroundContent` 合并到页面。首次进入、切换账号或评论/私信、手动操作后的刷新仍走原来的完整渲染。
  - 评论卡片、私信卡片、帖子分组加 `data-refresh-key`（消息 ID / 帖子键），新消息插到前面时不会把已有卡片和展开状态错位。
  - `bindCommentPostGroups`：每个帖子分组只绑定一次 `toggle`（`WeakSet`），展开时读取最新一次渲染的分组数据；原实现每次重画都在新节点上绑定，原位合并后会在同一节点上重复绑定。
- `public/workspace-interactions.js`
  - 评论收件箱：选中、筛选、键盘选择改为挂在容器上的 `onclick` / `onkeydown`，点击时从页面查找当前节点、从最新数据（`latestComments`）取消息；详情区的转发按钮按消息 ID 与动作类名查找页面上的原按钮再点击。
  - 私信：会话切换、搜索改为 `onclick` / `oninput`，卡片带 `data-private-key`，所选会话保存在模块状态，按账号区分。
  - 原因：原位合并时，页面上保留的是旧节点，`addEventListener` 绑定在旧节点上的闭包会引用旧数据，新插入的节点又会带着离屏节点的闭包，点击后可能操作不在页面上的节点。

后端、接口和轮询频率（3 秒）未改动。

## 决策与取舍

沿用已有的 `patchBackgroundContent`，不另写一套合并逻辑。只有定时刷新走原位合并：用户主动操作（切换账号、标记处理、删除等）之后仍完整渲染，结果更直接，也不需要处理操作中途的合并。

## 追加：下拉框、分段控件与展开箭头（macOS 风格）

用户指出首页“近 7 天 / 近 30 天”等弹出选择框太传统，要求用前端设计 skill 审核并向预览中的 macOS 风格靠拢。

- **下拉框**（新增 `public/ui-select.js`、`public/ui-controls.css`）：页面上的原生 `<select>` 外面包一层按钮，点开为毛玻璃弹出菜单，当前项带对勾，悬停项为主色高亮条，平台选项带官方图标，支持方向键、回车、Esc。原生 select 仍在原位（透明、可聚焦、不接收鼠标），键盘、读屏、测试脚本的 `selectOption` 和 `app.js` 的 `onchange` 不变；页面重绘或后台原位合并后由 MutationObserver 在同一帧补回外观。只在内容变化时更新按钮文字，避免与观察器互相触发。
- **运营总览周期**：只有两个选项，改为分段控件（点一下切换），原 select 保留在控件内并派发 change，刷新逻辑不变。
- **展开 / 收起**：“更多分析”“采集状态与设置”“处理详情”等折叠区去掉浏览器默认三角，改为旋转的小箭头。
- **字体与勾选框**：优先使用系统字体（Mac 为 SF / 苹方，Windows 为 Segoe / 微软雅黑）；勾选框、单选框跟随主题主色。
- 修正两处旧样式冲突：评论页 `.message-poll-control` 会隐藏 label 内所有 span（控件内部元素强制显示）；发布页“内容来源”原有外框与箭头去掉，由新控件占满整行。

浏览器验证：总览平台筛选选“抖音”后已发布数与口径随之变化，分段控件切到“近 30 天”后口径变化且平台筛选保持；评论页账号与采集间隔、发布页内容来源、AI 服务页模型选择均显示新控件，日间与夜间正常。
