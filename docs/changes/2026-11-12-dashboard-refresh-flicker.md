# 后台数据更新与页面闪烁修复

日期为 2026-11-12，Australia/Sydney。基线为 main 的 f553320。本轮修复已应用到当前 3190 本地预览，工作区包含 Claude 的既有 UI 改动，提交与推送均待用户后续安排。

## 背景与目标

用户通过 UU Remote 观察到管理界面持续出现刷新感，要求查明 RPA 是否正在操作主浏览器。用户明确要求保留自动采集与数据更新，并让后台变化平稳显示，保护正在进行的操作，同时按 Docs as Code 在实际工作区留下上下文。

## 变更与影响

- `public/app.js` 的运营看板仍每 30 秒读取数据。后台读数先比较展示输入，忽略顶层及 analytics 的响应生成时间。无变化时只更新显示时间，有变化时生成离屏结构并原位同步现有节点。手动刷新、筛选及首次进入继续走原入口。
- 平台账号仍使用原 5 秒 bootstrap 轮询。相同状态保留卡片，账号、队列或连接状态改变时原位同步。平台动作执行期间暂缓画面同步，请求结束后恢复下一轮状态更新。
- `public/background-dom.js` 按 ID、稳定数据键及结构匹配节点，更新文字、属性和操作处理器，保留展开状态、表单当前值、节点身份与局部光效。平台提示区在同一离屏结构内组装，避免独立移除再插入。
- `public/workspace-presentation.js` 为动态行提供稳定键，复用粒子球更新入口。`public/ai-orb.js` 保留动画相位，离屏结构创建期间跳过画布启动。`public/index.html` 与模块引用更新资源版本。
- 两份专项测试覆盖无变化、有变化、晚到响应、操作期间保护和 DOM 身份。操作说明补充在 [前端工作区](../frontend-workspace.md)。

## 决策与取舍

保留既有采集、消息、账号和发送合同，以及原轮询频率。页面展示采用数据比较与原位同步，采集端继续独立工作。输入、确认弹窗或平台动作进行期间暂缓展示更新，下一轮读取恢复同步。

后台生成时间不代表业务数据改变。真实指标、账号状态、设备心跳、业务统计与平台队列继续参与比较。长期运维结构沿用现有实现，本次无需另立 ADR。

## 验证与证据

- 修改前，在真实 3190 标签页观察 30 秒，运营接口读取 2 次，dashboard 与 canvas 身份均改变，内容区发生 5 条直接子节点移除记录。这些移除来自一次整体渲染及后续布局整理，不能解释成 5 次页面导航。
- 修改后连续观察运营总览 183 秒，运营接口读取 6 次、bootstrap 读取 37 次，内容区直接子节点移除为 0，dashboard 与 canvas 身份保持一致。“更多分析”持续展开。
- 临时显示探针在浏览器内存中模拟已发布数、AI 回复数及新增一条记录，界面即时更新，原节点和展开状态保留。下一次真实轮询恢复服务端读数。该模拟仅用于展示验证，服务端数据库没有接收写请求。
- 平台账号页最终观察 75 秒，bootstrap 读取 16 次，直接子节点移除为 0，管理面板保持展开。模拟账号名称变化即时显示，真实轮询恢复原名称，展开状态继续保留。
- 专项和相关现有测试通过，命令为 `node --test test/background-dom.test.js test/background-refresh.test.js test/platform-runtime-performance.test.js test/platform-analytics.test.js test/docs-as-code.test.mjs`。共 65 项通过，0 失败，0 跳过，其中本轮专项 21 项。
- `node --check` 检查本轮 JavaScript。临时探针、诊断按钮和模拟显示参数在交付前清理，常规入口重新加载原始服务端数据。

## 部署与回退

3190 直接从当前 checkout 提供静态文件，本轮应用方式为更新这些前端资源并重新加载浏览器。上一轮服务重启的 PID 从 77675 变为 17546，`/api/health` 和页面均返回 200。

源码回退应只恢复本轮增量。工作区同时包含 Claude 既有 UI 改动，回退以本轮修改前的私有备份为比较依据，保留其布局、弹窗、图标和文案。数据恢复按原部署流程进行。

Dockerfile 的明确 COPY 与有效 `.dockerignore` 排除开发记录，Windows 安装器按运行目录清单复制，仅单独加入安装说明。本次完成构建隔离配置审查，镜像和安装包的产物验证留待正式发布。

## 未完成与下一步

本次验收覆盖 3190 本地预览的页面轮询和原位更新，以及隔离的显示变化。平台真实采集、发送、发布、RPA 登录窗口和 UU Remote 接收端画面需要各自对应的运行验收，不能由本轮浏览器结果推定。

接手者先读本记录与相关测试，从 3190 的运营总览和平台账号开始，至少跨越两个自动刷新周期，确认数据更新、操作状态和节点身份。需要基线对比时，使用独立源码副本或 worktree，避免在为用户提供预览的 public 目录上切换版本。

## 上下文与关联

用户截图中的 external SIGTERM 来自本会话按用户要求重启 3190 时发出的正常关闭信号。Claude 当时推测为测试清理或实例锁，当前进程证据已校正该来源。
