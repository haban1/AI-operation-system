# 2026-11-12：工作台外框重构与页面细节（对齐设计预览）

日期：2026-11-12。基线 `a6f33c0`（main）。状态：已修改，本地验证中；未提交、未推送、未部署。

## 背景与目标

用户指出现有界面与最初的设计预览仍有明显差距，要求以 UI、风格和交互为核心，参考成熟做法，更激进地重构前端，使其更易用、更清晰，功能保持不变。

逐页截图对照预览后，最大的差距在外框：顶部是“大标题栏 + 下划线栏目条”两层；侧栏缺少搜索、计数和 AI 员工状态卡，底部是旧的“运行状态”折叠区；没有全局快捷跳转。页面层面，问题记录直接铺开原始报错堆栈，转人工记录显示整串技术 ID，发布任务与转人工的平台没有图标，微信客服的未连接提示仍是旧横幅。

## 变更与影响

- **外框（新增 `public/app-shell.js`、`public/app-shell.css`）**
  - 顶栏改为悬浮毛玻璃工具条：左侧“分组 / 页面名”，原栏目切换 `#workspaceSubnav` 移入顶栏并显示为分段控件，右侧搜索按钮。元素与 `data-workspace-item` 不变。
  - 侧栏改为悬浮圆角面板：品牌下方加“搜索页面或操作 ⌘K”；“用户互动”“发布管理”“系统设置”显示待人工、排队发布、未处理问题的计数（来自 bootstrap 的 `stats`）；选中项白底卡片加左侧主色条。
  - 底部“运行状态”折叠区的标题改为 AI 员工状态卡：运行 / 暂停、五个平台的登录就绪情况（官方图标）、可执行平台数。点开后仍是原来的云端服务、采集服务、AI 模式与全局运行开关。
  - ⌘K / Ctrl+K 命令面板：搜索 20 个页面（含同义词，如“定时”找到发布排期）和两个操作（切换日间 / 夜间、刷新当前页面），方向键选择、回车打开、Esc 关闭。跳转通过 `location.hash`，沿用原有路由。
- **`public/app.js`**：`commitBootstrap` 派发 `app:bootstrap` 事件供外框读取；`renderIssues` 渲染后调用一次 `presentInteractions()`；转人工记录表的平台单元格加官方图标、用户 ID 加完整 `title` 并截断显示；导入 `platformLogo`。不改业务逻辑。
- **`public/workspace-interactions.js`**：新增 `presentIssues`，问题卡片标题下只显示一句可读原因，原始报错、关联对象与阻断信息收进“技术详情”，“人工已处理”为主按钮；发布任务行的平台列显示“图标 + 名称”。
- **样式**：`workspace-v2.css` 补充问题记录、转人工表格、任务平台、微信客服未连接提示的样式；`ui-controls.css` 为“技术详情”加旋转箭头。`index.html` 引入新文件并更新缓存版本号。

后端、接口、轮询与所有操作按钮的行为未改动。

## 决策与取舍

- 参考：macOS 侧栏（source list）与工具条内分段控件、Linear / Raycast 的 ⌘K 命令面板、Vercel 的状态圆点。
- 外框通过独立模块增强原有 DOM，不重写 `app.js` 的导航渲染；`#nav`、`#workspaceSubnav`、`#masterSwitch`、`#refreshBtn` 等原节点与事件保留，原有测试依赖的选择器不变。
- 计数只显示接口已有的数字，没有对应数据的分组不显示徽标。
- 命令面板只做跳转和两个无副作用的操作，不放入全局运行开关、采集、发送等有副作用的动作。

## 追加：用户反馈修正与用户互动页对齐（同日）

用户在 3100 上指出：平台运营数据为什么没有自动采集、AI 数字员工卡片内容被截断、总览底部几条折叠项应叠成一组；并要求小程序对话、转人工记录与评论/私信布局一致，其他页面同样紧凑、自适应，且确认功能流程没有丢失。

- **平台运营数据的说明**：经核对 `src/services/platform-analytics-scheduler.js`，系统每 30 分钟只为“已启用且登录状态为 READY”的抖音、视频号、B站、微博账号创建只读采集任务，由本机采集服务执行；小红书不在支持范围。当前账号均未登录、采集服务未连接，所以一直“等待首次采集”。面板空状态改为说明这条规则，并按平台列出状态（官方图标 + 原因），有未登录账号时给出“去‘平台账号’登录”的链接；有数据时才显示更新频率说明。`#collectOperationsAnalytics` 与 `.operations-analytics-account` 不变。
- **AI 数字员工卡**：右侧内容列 `min-width:0`、账号行改为三列网格，状态标签不再超出卡片；卡片较窄时（容器查询 ≤520px）粒子球移到上方。
- **总览折叠项**：“更多分析 / 回复与调用统计 / 运行详情 / 设备与登录状态”合成一张卡片 `.v2-fold-group`，每行之间用分隔线，收起时总高约 190px，展开哪行只撑开哪行；各项加 `data-refresh-key`，后台原位刷新时保持展开状态。
- **顶栏**：只有一个栏目的页面（如运营总览）不再重复显示分段控件。
- **小程序对话**：与评论收件箱同结构——左侧“状态”列（原 `.mini-program-filter` 按钮移入，事件与 `data-filter` 不变）/ 中间会话列表 / 右侧详情，三栏同宽同圆角、顶部对齐；去掉原工作区大外框；“连接与运行设置”等折叠区使用同样的旋转箭头。
- **转人工记录**：与评论/私信一致——顶部一句说明 + “刷新状态”；左侧“企业微信通知”状态列（通知重试中 / 已成功通知 / 全部，计数取自原统计），点击只在页面上筛选已加载的行；右侧明细表格紧凑化。`#refreshHandoffs` 与接口不变。

功能核对：在 3190 依次打开全部 20 个页面，均无脚本错误；逐页核对关键操作控件仍在（总览筛选与采集、发布表单与提交/定时、评论私信的导出/账号/立即采集/采集间隔、小程序筛选与连接设置、转人工刷新、知识库表单、平台账号启停/智能回复/登录、AI 服务保存/测试/清除、企微通知保存/测试/清除、问题记录处理按钮）。创作方式与创作设置为内嵌的创作工作台，正常加载。

## 追加：平台账号页、回归修复与全系统溢出检查（同日）

- **平台账号页**：顶部原“4/5 可执行 · 4/5 已开启”一行（`.platform-runtime-page-head`，测试依赖其可见）改为状态条：模式（模拟模式 / 真实账号模式）、采集服务是否连接、“N 个平台已开启 · N 个可以执行任务”，悬停有解释；原折叠在“批量管理”里的四个按钮直接显示并改为易懂的文字（全部开启 / 批量打开登录窗口 / 全部停止 / 查看问题），按钮 ID、事件与 `app.js` 源码中的原文案不变；“模拟模式”长说明与“安全关闭语义”合并为一个“使用说明”折叠区，改写为“如何登录平台账号”“停止平台后会怎样”。
- **回归修复 1（手机宽度横向溢出）**：390px 下侧栏宽度仍为 390px，加 8px 外边距后超出屏幕 8px，导致 `publish-flow-ui`、`browser-status-ui` 的“不横向溢出”断言失败。手机宽度下侧栏与顶栏改为自适应宽度，状态卡收紧。
- **回归修复 2（多发一次 bootstrap 请求）**：外框模块启动时额外请求一次 `/api/bootstrap`，使 `publish-layout-sync` 中按请求次数控制的测试一直等待（超时）。改为由 `commitBootstrap` 把数据存到 `window.__appBootstrap`，外框直接读取，不再发请求；外框模块不再调用任何接口。
- **全系统溢出检查**：脚本在 1440、1280、390 三种宽度下依次打开 18 个页面并展开所有折叠区，检查页面横向溢出、内容超出内容区（自测：人为插入 3000px 元素能被检出）、被裁切的文字。三种宽度均无问题。
- **接口核对**：前端读取的 23 个 GET 接口在 3100 与 3190 上逐个调用，20 个返回成功；`/api/rag/files`、`/api/rag/answer-profile` 返回 `RAG_ADMIN_DISABLED`（本机未启用知识库服务），`/api/wechat/robot-admin` 提示未配置 `WECHAT_ROBOT_ADMIN_URL`，均为本机环境配置所致，改动前同样如此；本轮后端代码与已推送的 `a6f33c0` 相同。
