# 多来源热点采集

## 使用入口

智慧驱动 → 内容制作 → 从热点中选 → 管理采集来源与关键词。修改后先点“保存来源”，再点“刷新热点”。可按来源及标题/摘要关键词筛选，选中热点后沿用现有文稿、视频和多方案创作流程。

| 来源 | 采集内容 | 配置与限制 |
| --- | --- | --- |
| GitHub | Trending 周榜中匹配 AI 关键词的项目及 Star 数据 | 保留原有采集逻辑，可开关 |
| RSS/Atom | 订阅最新文章、摘要、原文链接和发布时间 | 每行 `名称 | URL`，最多 10 个订阅，每个最多 30 条；默认 IT之家 |
| 微博 | 热搜词、榜单位置、热度和搜索链接 | 复用本机平台浏览器读取官方热搜网页，需平台运行；见下方修复说明 |
| 小红书 | 一周内、按最多点赞排序的关键词搜索笔记 | 1–3 个关键词，每词最多 20 条；图文/视频/不限；需本机 MCP 服务登录 |
| Hacker News / Reddit | AI 社区讨论 | 保持为辅助线索，不直接作为选题卡片 |

RSS 是订阅更新，小红书是关键词搜索结果，不代表全站热榜。各平台数值保留原单位，不进行跨平台热度排名。采集失败保留原来源历史结果并标注，关闭来源后在下次刷新移除其结果。

2026-11-05 微博已改为浏览器网页采集，解决旧接口直接请求的 403，配置与验证见 [微博热点浏览器采集修复](微博热点浏览器采集修复-20261105.md)。下方 2026-11-04 的记录保留为历史验证结果。

小红书在来源设置中点击“显示登录二维码”，用手机 App 扫码，再点击“检查小红书登录”。登录成功后刷新热点。选择小红书内容进行研究时，再读取对应笔记正文；正文不足会停止并提示补充资料。此功能不下载视频原片、图片素材或自动提取视频字幕。抖音、视频号尚未接入。

## 接口与数据

入口位于 `engines/ai-signal-studio`，由主应用的管理员登录代理 `/integrations/ai-signal/` 提供访问。

- `GET /api/state`：返回 `config.sources`、`feed` 和任务状态。
- `POST /api/sources-config`：请求 `{ "sources": { ... } }`，保存来源配置，任务运行时返回 409；与模型设置分开保存，不落盘 Token。
- `POST /api/collect`：后台采集，返回 202，通过 state 读取完成状态。
- `POST /api/xhs-status`、`POST /api/xhs-login-qr`：检查登录、获取短期二维码；受任务锁保护。
- `POST /api/draft`、`/api/build`、`/api/compare`：新增 `candidate_id`，由服务端解析当前选题；GitHub 继续走 repo 流程，其他来源走 topic 研究流程。

`sources` 包含 `github`、`weibo`、`xiaohongshu`、`hackernews`、`reddit` 布尔开关，`xhs_keywords` 字符串数组，`xhs_note_type`（不限/图文/视频），以及 `rss: [{name,url}]`。

`data/feed.json` 升级为 `schema_version: 2`。选题新增 `source_key`、`content_type`、`metrics: [{label,value,display?}]`、`discovery`、`archive`、`stale`；保留 `id/title/url/description/collected_at` 和 GitHub 原有字段。新适配器还提供 `external_id`、`published_at` 等信息。每次结果归档到 `data/capture-YYYYMMDD-HHMMSS-ffffff/`。生成任务记录不可变的 `{archive,id}`，不接受浏览器上传的正文充当已核实资料。

新增来源应在 `scripts/source_collectors.py` 中实现解析和采集，在 `source_jobs` 注册，并添加配置开关及界面入口。具有标准 RSS/Atom 的网站可直接在页面添加，无需修改代码。仅有网页、登录接口或不同鉴权协议的平台仍需适配器。

## 部署与回滚

本机实际运行项目为 `tianhe-dev`，只更新 signal 服务：

```powershell
docker compose -p tianhe-dev -f compose.yaml -f compose.wechat.yaml -f compose.workbench.yaml build signal
docker compose -p tianhe-dev -f compose.yaml -f compose.wechat.yaml -f compose.workbench.yaml up -d --no-deps --no-build signal
```

本次使用已保留的旧镜像为基础增量构建（没有修改依赖），部署镜像 `tianhe-signal:multi-source-20261104`。运行数据继续挂载 `runtime/workbench/signal/{data,runs,config}`。若需回滚，把 compose.workbench.yaml 中 signal 镜像改回 `tianhe-signal:brief-schema-20261030`，执行上述 up 命令，不运行 build；原镜像仍保留。

小红书地址通过服务端环境变量 `SIGNAL_XHS_MCP_URL` 配置。Docker Desktop 默认 `http://host.docker.internal:9200/mcp`，浏览器不能修改地址。客户端只允许搜索、详情、登录检查和二维码四类 MCP 工具。

本机已有 `xiaohongshu-mcp` 缺少 Chrome，本次用附带 Dockerfile 补齐浏览器，保留原有端口和挂载。后续重建应继续带上覆盖文件，否则原 compose 会恢复缺少浏览器的镜像：

```powershell
docker build -f deploy/workbench/xhs-browser.Dockerfile -t tianhe-xiaohongshu:browser-20261104 .
docker compose -p local -f E:\projects\weixin_robot\wechat-robot-client\.deploy\local\docker-compose.yml -f deploy/workbench/xhs-browser.override.yaml up -d --no-deps --no-build xiaohongshu-mcp
```
