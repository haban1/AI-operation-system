# 运营后台账号与业务记录归属设计

日期：2026-09-08

状态：已暂缓。用户于 2026-09-08 决定继续使用当前后台账号，先清空任务中心、评论与私信及相关记录；本设计留待后续讨论，尚未实施多账号功能或所有权迁移。

## 1. 目标与用户已确认的范围

用户希望任务中心、评论与私信等业务记录跟随运营后台登录账号保存。每个后台账号独立管理自己的社媒登录、任务、消息和转人工记录；知识库与企微配置共用。

最终行为：

- 以后台账号 A 登录，只能查看和操作 A 的业务记录及社媒账号。
- 新建后台账号 B 后，B 的业务记录为空，五个平台均等待配置和登录。
- 从 A 切换到 B，再切回 A，A 的历史记录和社媒登录资料仍然保留。
- 自动采集消息归属于对应社媒账号的后台所有者；网页当前由谁登录不决定消息归属。
- 已有业务数据及现有社媒登录资料迁入当前 `admin` 对应的内部账号，不删除、不重新采集历史数据。
- 知识库、已发布的 RAG 版本、通用回复规则与企微接收配置继续共用。

前一轮“清空所有社媒账号记录”的操作已取消。当时仅执行了只读检查，没有删除、搬移、退出社媒账号或修改生产数据。

## 2. 当前项目约束

当前登录代码在 `src/services/auth.js`、`src/server.js`，只校验 `.env` 中的一组 `ADMIN_USERNAME` / `ADMIN_PASSWORD`，会话以用户名作为主体。数据库尚无后台用户表，`accounts` 保存的是社媒账号。

任务、消息、会话、通知、队列和浏览器控制记录保存在同一个 `data/mvp.db`。部分查询按社媒 `account_id` 过滤，但任务中心、消息列表、导出、统计和多个详情接口仍使用全局数据。

Local Agent 的适配器、运行控制及浏览器管理主要按平台编码缓存。每个平台当前使用固定的浏览器资料目录。只给页面列表增加筛选条件，无法实现已经确认的独立社媒登录和后台任务归属。

这是同一个本地后台内的多账号隔离调整，包含登录、持久化、后台接口和执行端。共享 RAG 不进行拆库；本次不新增公网部署、社媒自动注册、账号之间的数据转移或跨账号代操作功能。

## 3. 方案选择

| 方案 | 特点 | 结论 |
| --- | --- | --- |
| 同一 SQLite 数据库，业务记录关联固定后台用户 ID | 可以保留现有外键和队列链路，共享知识及配置只保存一份；必须覆盖全部业务读写和后台执行入口 | 采用 |
| 每个后台账号使用单独业务数据库，再单独管理共享知识及配置 | 数据文件独立，但现有单连接、调度、外键、配置读取和备份流程需要跨库重构 | 本次不采用 |

同库方案的隔离边界由服务器鉴权、查询范围、数据关联约束与执行端账号路由共同落实。浏览器不传递可自行决定的记录所有者。

## 4. 账号与会话

新增后台用户表 `operator_users`，使用不可变的整数 ID。用户名仅用于登录和显示，业务归属不跟随用户名或密码变化。

用户记录包括用户名、显示名称、密码散列、角色、启用状态、会话版本和时间字段。密码采用 Node 内置密码派生函数及独立随机盐，数据库不保存明文密码。

现有配置中的管理员在首次迁移时成为初始管理员，保留现有登录凭据。后续创建的后台用户写入数据库。初始化必须幂等，不得在每次启动时覆盖已经修改的密码或重新生成用户。

管理员可以创建后台用户、停用用户和重置密码。不提供公开注册；不得停用最后一个启用的管理员。管理员的普通业务页面仍只展示其自己的数据，账号管理权限不自动授予跨账号业务访问权限。

登录会话携带固定用户 ID 和会话版本。请求时校验用户是否启用；重置密码、停用和退出登录能够使对应会话失效。旧版会话要求重新登录，不把无法确认归属的会话静默映射到任意账号。

未开启认证的开发/测试模式统一使用明确的兼容账号，不能通过用户名参数模拟其他用户。生产环境延续当前 `AUTH_ENABLED=true`。

## 5. 数据范围

| 数据 | 归属规则 |
| --- | --- |
| 社媒账号及登录身份 | `accounts` 增加 `owner_user_id`，每个后台用户拥有自己的一套社媒账号 |
| 发布、定时发布、各平台发布结果 | 根任务保存所有者；所有发布目标必须属于同一所有者 |
| 评论、私信、会话、去重、采集游标、回复批次 | 从社媒账号继承所有者，后续处理不重新按网页会话分配 |
| 转人工、通知、知识缺口、业务异常 | 从来源任务、消息或社媒账号继承所有者，详情、列表和操作使用同一范围 |
| Agent 队列、浏览器命令、会话及业务证据 | 保存可验证的所有者和社媒账号，执行及回执不得修改归属 |
| 用户工作中的素材知识草稿、小智测试记录 | 跟随发起操作的后台账号；明确加入共享知识库后，发布内容按共享知识流程提供给其他账号 |
| 知识库、已发布文档、知识别名、通用转人工说法和语义规则 | 继续共用，沿用现有审核、测试及发布流程 |
| 企微、AI 服务连接及物理设备配置 | 继续共用；密钥和连接配置由管理员维护，普通账号获得运行所需的状态信息 |

关联表可以通过根记录继承所有者；用于独立调度和直接查询的根实体必须显式保存所有者。涉及多个实体的写入同时校验所有者一致，不能只校验其中一个 ID。

用户名修改不重建记录归属。社媒平台编码、业务消息类型和后台所有者使用不同字段，不复用现有社媒 `account_id` 表示后台用户。

消息唯一键、发布防重键、通知防重键、浏览器命令防重键及会话命名空间都必须覆盖实际账号范围。相同外部消息 ID 在不同社媒账号下可以分别存在；同一账号内仍然去重。

## 6. 后端接口与自动任务

增加统一的身份与所有权服务，供身份验证、所属账号查询及关联记录校验调用。后台接口从有效会话取得所有者；客户端提交的 `owner_user_id` 不能覆盖服务器推导出的值。

隔离覆盖任务列表和详情、发布历史和定时任务、消息列表和 CSV 导出、转人工记录、知识缺口、异常诊断、队列详情、账号状态、浏览器控制、业务证据及运行概览统计。跨账号访问具体资源统一返回不可用结果，不泄露记录正文、数量或存在性。

写操作同时校验目标账号、任务、消息、重试源、通知与浏览器会话等关联对象。混入其他所有者 ID 的批量操作整体拒绝，避免部分执行。

自动采集、自动回复、定时发布、失败恢复、人工转接通知与回执依据数据库中的所有者和社媒账号执行。用户退出网页不会把后台任务交给后来登录的人；原任务继续遵守原账号的启停状态。

Agent 继续是本机可信执行服务，使用已有服务凭据。服务端根据已领取的任务、设备和社媒账号验证回执归属；从客户端或回执额外提交一个后台用户 ID，不能改变任务所有者。

旧的单平台操作接口在多账号情况下必须解析到当前用户唯一的社媒账号；无唯一目标时拒绝执行，不选择平台下的第一条账号记录。

## 7. 独立社媒登录与运行控制

保留 `platforms` 作为共享平台目录。后台账号的总开关、平台启停、智能回复开关和业务阻断状态按所有者保存。关闭 A 的平台不得停止 B 的同平台任务或浏览器。

物理 Local Agent 由服务统一管理：只要存在需运行的账号就保持可用，全部账号暂停后才可关闭。管理员停止本机服务仍是整机操作，和账号自己的总开关区分。

适配器、浏览器上下文、受管页面、登录轮询和恢复缓存改为按社媒账号 ID 路由，并同时校验平台编码。操作协调器按实际账号和通道协调，同平台不同账号不得复用登录上下文。

新账号浏览器资料目录由服务端生成，例如 `data/browser-profiles/operators/<固定用户ID>/<社媒账号ID>`；路径不直接采用用户提交的用户名或目录。旧账号继续使用现有已验证目录，并把绑定保存到对应账号。

同一个受管社媒登录资料只属于一个后台账号。本次不提供复制登录凭据或同时把同一份资料绑定给多个后台账号的入口。账号实际平台身份一旦识别，与绑定不一致时暂停相关执行并要求重新绑定，避免在旧账号槽位直接换号后误处理旧任务。

关闭或停用账号时，只释放该账号的浏览器和相关运行资源。未确认新账号登录前不得使用其他账号的浏览器补位，也不得复用全局已登录状态。

## 8. 页面行为

沿用现有登录页，登录后在操作人区域显示当前后台账号。新增仅管理员可见的后台账号管理入口，用于创建、停用及重置密码；创建用户后不自动登录任何社媒平台。

现有任务、消息和转人工页面的交互保持一致，服务器返回当前用户范围内的数据及统计。新用户显示空列表及待登录状态，不展示旧用户的历史业务数据。

切换后台登录账号后清理页面中的旧数据、弹窗、草稿、选中账号和计时器。正在返回的旧会话请求通过会话代次检查丢弃，不能覆盖新账号页面。切换仅发生在网页会话，后台任务保留原始所有者。

普通后台账号可以使用共享知识库的现有功能；共享连接配置界面区分查看状态与管理员修改权限。共享企微通知带上后台账号和社媒账号标识，方便同一接收群区分来源。

## 9. 现有数据迁移与恢复

实施前使用数据库一致性备份保存当前数据库，记录原知识库、规则、配置以及业务表数量。独立保存迁移前的账号与浏览器目录绑定，现有社媒登录文件不搬移、不清除。

迁移步骤：

1. 在备份副本上演练新增后台用户、所有者字段、索引及运行状态迁移。
2. 将当前 `admin` 创建为固定内部用户，把已有账号、业务记录、队列、通知和相关状态归给该用户。
3. 缺少关联 ID 的历史通知或执行记录也归入初始管理员，不能被新用户查询到。
4. 为管理员迁入原运行开关和平台设置；新用户默认暂停、未登录。
5. 校验外键、数量、知识及配置内容摘要、账号与浏览器映射，并验证重复启动不重复迁移。
6. 正式应用时暂停本地执行，在备份与验证都通过后迁移生产数据库，恢复后台服务并保持运行暂停，交由用户决定何时恢复平台运行。

回退同时使用迁移前代码与数据库备份，防止旧代码把多账号数据作为全局数据读取。迁移失败必须回滚，不启动处于半迁移状态的服务。新增账号之后产生的数据不得被静默覆盖回旧备份。

知识内容及发布版本不重建；旧历史继续存在。新用户的空白列表来自所有权隔离，而不是清空数据库。

## 10. 实现边界与模块

- `src/services/auth.js`：多后台账号身份、密码及会话验证。
- 新增后台账号和所有权服务：用户生命周期、稳定 ID、所属资源校验。
- `src/db.js` 及迁移模块：新增表、所有权、索引、旧数据迁移及幂等检查。
- `src/server.js`、通知、运行控制、浏览器命令与相关业务服务：接口隔离、归属传播与回执验证。
- `agent/local-agent.js`、适配器注册、运行协调器及浏览器管理：按社媒账号选择独立登录环境。
- `public/app.js` 及必要样式：后台账号管理、当前账号显示、账号切换时的状态清理。
- 认证、数据库迁移、所有权、队列执行和浏览器隔离测试：覆盖完整读写链路。

当前工作目录有既有未提交功能和测试修改。实施使用包含当前有效改动的隔离工作副本，保留这些修改；不得覆盖或回退它们，也不得把其他功能分支自动合并到主目录。

## 11. 验收条件

1. 管理员原登录有效；A、B 两个不同后台用户均能独立登录，新用户最初无业务记录。
2. 原发布、消息、会话、转人工、通知及队列记录归 `admin`，数量和关联保持一致；知识库、规则及共享配置内容保持一致。
3. A、B 的列表、详情、统计、CSV 导出和证据访问不混合；通过手工请求另一用户的 ID 也无法读取、删除、重试或回复其记录。
4. 两个后台用户在相同平台拥有不同受管浏览器资料；打开、轮询、停止、异常恢复及重启均定位到正确社媒账号。
5. 自动采集及定时任务在用户退出网页后仍保持原所有者；另一个用户登录不改变原消息归属。
6. 同一外部消息在不同账号下可独立保存，同一账号内重复采集保持去重；转人工接管状态只作用于所属账号的对应用户会话。
7. 关闭 A 的总开关或平台开关只暂停 A；B 的运行状态和浏览器继续遵守 B 自己的设置。
8. 同浏览器退出 A 后登录 B，旧请求、弹窗和轮询不再写入页面；切回 A 能重新查看 A 的历史。
9. 重置密码、停用和退出登录后的旧会话失效，普通用户不能调用后台账号管理或修改共享连接密钥。
10. 迁移副本通过完整性、外键和重复运行检查；生产应用后验证以上数据保留与隔离结果。

测试使用隔离数据库、模拟 Agent、临时浏览器资料及本地通知桩。验证所有权不需要发送真实社媒消息或触发真实企微通知。
