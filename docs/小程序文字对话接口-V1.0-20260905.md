# 小程序文字对话接口 V1.0

- 版本：V1.0
- 日期：2026-09-05
- 对接双方：小程序服务器与天河 AI 数字员工运营平台
- 数据范围：仅支持用户文字消息

本文是小程序服务端的联调合同。小程序前端不直接调用本接口；调用链应为“小程序前端 -> 小程序服务器 -> 受限公网反向代理 -> 本地 AI 平台”。

## 1. 接入边界

公网只允许以下一个请求：

```text
POST /open-api/v1/mini-program/messages
```

- 路径必须完全一致，不能增加末尾 `/`、查询参数或其他子路径。
- 生产环境必须使用 HTTPS。
- 只接受 UTF-8 JSON 文字消息，不支持图片、语音、视频、文件、富文本或附件字段。
- `appId` 和共享密钥由双方线下约定。共享密钥必须由密码学安全随机数生成器（CSPRNG）生成至少 32 个随机字节，再用 Base64 或十六进制编码后存入环境变量；至少 32 个字符只是平台用于发现明显缺失或截断配置的格式下限，不等同于足够的随机熵。密钥不得写入前端、仓库、日志或截图。
- 小程序每开启一次新的咨询，都必须生成新的 `conversationId`。特别是原会话已转人工后，不得复用原 `conversationId` 开启下一次咨询。
- 本平台只通过回调发送 AI 文字回复，不发送“已转人工”提示，也不等待或接收人工认领、处理完成、会话结束等状态回调。
- 人工客服在小程序自己的客服系统中继续对接；本平台后台没有人工回复入口。

## 2. 提交用户消息

### 2.1 HTTP 请求

```http
POST /open-api/v1/mini-program/messages HTTP/1.1
Host: <公网接入域名>
Content-Type: application/json
X-Mini-App-Id: <双方约定的 appId>
X-Timestamp: <Unix 秒>
X-Nonce: <本次请求的随机字符串>
X-Signature: <HMAC-SHA256 小写十六进制>

{
  "appId": "<双方约定的 appId>",
  "conversationId": "consultation-demo-001",
  "messageId": "message-demo-001",
  "userId": "user-demo-001",
  "text": "接口联调测试消息",
  "sentAt": "2026-09-05T09:30:00.000Z"
}
```

请求头规则：

| 项目 | 规则 |
|---|---|
| `Content-Type` | 使用 `application/json`；也接受唯一一个 `charset=utf-8` 参数。不接受其他媒体类型、重复参数或非 UTF-8 字符集 |
| `Content-Encoding` | 不允许；不要使用 gzip 等请求体压缩 |
| `X-Mini-App-Id` | 必填，必须与请求体和平台配置中的 `appId` 一致；去除首尾空白并进行 NFC 规范化后为 1 至 128 个 Unicode 码点，原始请求头也不得超过 128 个码点 |
| `X-Timestamp` | 必填，1 至 16 位十进制 Unix 秒；与平台服务器当前时间的差值不得超过 300 秒 |
| `X-Nonce` | 必填，1 至 128 个 Unicode 码点；同一 `appId + nonce` 在 10 分钟内只能使用一次 |
| `X-Signature` | 必填，64 个小写十六进制字符 |

建议小程序服务器使用 NTP 同步系统时间，并使用不可预测的 UUID 或安全随机值生成 Nonce。

### 2.2 JSON 字段

请求体必须是一个 JSON 对象，并且只能包含下列六个字段。六个字段均必填且类型必须为字符串。

| 字段 | 含义 | 规则 |
|---|---|---|
| `appId` | 应用标识 | 与请求头及平台配置完全匹配；trim + NFC 后 1 至 128 个 Unicode 码点 |
| `conversationId` | 一次咨询会话标识 | trim + NFC 后 1 至 128 个 Unicode 码点；同一会话只能绑定一个 `userId` |
| `messageId` | 用户消息唯一标识 | trim + NFC 后 1 至 128 个 Unicode 码点；`appId + messageId` 全局幂等，不能分配给另一条消息 |
| `userId` | 小程序用户稳定标识 | trim + NFC 后 1 至 128 个 Unicode 码点；用于识别曾经成功转人工的用户 |
| `text` | 用户文字 | trim + NFC 后 1 至 2000 个 Unicode 码点；不能只包含空白 |
| `sentAt` | 小程序服务器记录的消息发送时间 | 严格 ISO 8601，例如 `2026-09-05T09:30:00.000Z` 或带合法时区偏移的时间；日期和时分秒必须真实有效 |

补充限制：

- 原始 HTTP 请求体最大为 **32768 字节（32 KiB）**，包含 JSON 空白和 UTF-8 多字节内容。正好 32768 字节允许，32769 字节拒绝。
- 请求体必须是合法 UTF-8；不能依赖服务端替换无效字节。
- 不要增加 `type`、`attachments` 或任何未列出的字段，即使值为空也会被拒绝。
- 建议调用方在生成 ID 时就使用无首尾空白的 NFC 字符串，避免规范化后的回执 ID 与本地原字符串不同。

## 3. 签名算法

### 3.1 规范原文

签名原文严格按下列五段拼接，每段之间只有一个换行符 `\n`，末尾没有额外换行：

```text
HTTP_METHOD + "\n" +
REQUEST_PATH + "\n" +
X_TIMESTAMP + "\n" +
X_NONCE + "\n" +
SHA256_HEX(RAW_REQUEST_BODY)
```

对于消息接口：

- `HTTP_METHOD` 固定为 `POST`；
- `REQUEST_PATH` 固定为 `/open-api/v1/mini-program/messages`；
- `SHA256_HEX` 和最终 `HMAC-SHA256` 都输出小写十六进制；
- 最终签名为 `HMAC-SHA256(共享密钥, 签名原文)`。

**必须对实际发送的原始请求字节计算 SHA-256。** 不得先签名一个 JSON 对象，再由 HTTP 库重新序列化；也不得在接收端解析 JSON 后重新序列化验签。空格、换行、字段顺序或 Unicode 字节发生任何变化，都会导致签名不同。

### 3.2 超时与重试

网络超时、连接中断或可重试的 `5xx` 响应发生时：

1. 保持原业务 `messageId` 不变；
2. 重新生成当前 `X-Timestamp`；
3. 重新生成从未使用过的 `X-Nonce`；
4. 使用本次实际发送的原始字节重新计算签名；
5. 使用指数退避并设置最大重试次数，不能无间隔循环请求。

业务幂等由 `appId + messageId` 保证。重复提交同一个 `messageId` 会返回第一次的 `ACCEPTED` 结果，不会重复保存、处理、回复或通知。Nonce 只用于请求防重放：复用同一 Nonce 会得到 `401 MINI_PROGRAM_NONCE_REPLAY`，不会得到业务幂等回执。

对于 `MINI_PROGRAM_API_DISABLED` 或 `MINI_PROGRAM_CONFIGURATION_INCOMPLETE`，应联系平台运维修复配置，不要持续自动重试。

### 3.3 可运行的 Node.js 发送示例

示例要求 Node.js 18 或更高版本。本项目运行环境为 Node.js 24 或更高版本。示例不包含真实密钥或真实用户数据，运行前通过环境变量提供联调值。

```js
// send-mini-program-message.mjs
import { createHash, createHmac, randomUUID } from 'node:crypto';

const requestPath = '/open-api/v1/mini-program/messages';

function requiredEnv(name) {
  const value = String(process.env[name] || '').trim();
  if (!value) throw new Error(`Missing environment variable: ${name}`);
  return value;
}

const baseUrl = requiredEnv('MINI_PROGRAM_API_BASE_URL');
const appId = requiredEnv('MINI_PROGRAM_APP_ID');
const secret = requiredEnv('MINI_PROGRAM_SHARED_SECRET');
// 这里只防止明显缺失或截断；字符串长度不能证明密钥具有足够随机熵。
if (Array.from(secret).length < 32) {
  throw new Error('MINI_PROGRAM_SHARED_SECRET is missing or truncated');
}

const endpoint = new URL(requestPath, baseUrl.endsWith('/') ? baseUrl : `${baseUrl}/`);
const suffix = randomUUID();
const payload = {
  appId,
  conversationId: `consultation-demo-${suffix}`,
  messageId: `message-demo-${randomUUID()}`,
  userId: `user-demo-${randomUUID()}`,
  text: '接口联调测试消息',
  sentAt: new Date().toISOString()
};

// 后续 fetch 发送的就是这个 Buffer，签名后不要再次 JSON.stringify。
const rawBody = Buffer.from(JSON.stringify(payload), 'utf8');
const timestamp = String(Math.floor(Date.now() / 1000));
const nonce = randomUUID();
const bodyHash = createHash('sha256').update(rawBody).digest('hex');
const canonical = ['POST', requestPath, timestamp, nonce, bodyHash].join('\n');
const signature = createHmac('sha256', secret).update(canonical, 'utf8').digest('hex');

const response = await fetch(endpoint, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-Mini-App-Id': appId,
    'X-Timestamp': timestamp,
    'X-Nonce': nonce,
    'X-Signature': signature
  },
  body: rawBody
});

const responseText = await response.text();
console.log(response.status, responseText);
if (response.status !== 202) process.exitCode = 1;
```

PowerShell 运行方式：

```powershell
$env:MINI_PROGRAM_API_BASE_URL='https://<公网接入域名>'
$env:MINI_PROGRAM_APP_ID='<双方约定的 appId>'
$env:MINI_PROGRAM_SHARED_SECRET='<由至少 32 个 CSPRNG 随机字节编码得到的 Base64 或十六进制密钥>'
node .\send-mini-program-message.mjs
```

双方必须把环境变量中的 Base64 或十六进制编码文本按 UTF-8 原样作为 HMAC key，不要在签名前再次解码；否则双方使用的 key 字节不同，签名无法匹配。上述占位符不是可用密钥，联调和生产应分别生成独立密钥。

## 4. 接收回执

所有 JSON 响应均为 UTF-8，带 `Cache-Control: no-store`。

### 4.1 `ACCEPTED` 接收回执

HTTP `202`：

```json
{
  "ok": true,
  "accepted": true,
  "messageId": "message-demo-001",
  "status": "ACCEPTED"
}
```

`ACCEPTED` 是统一接收回执，具体持久化结果取决于接收时的会话状态，不能一概理解为已经创建后台处理任务：

| 接收时的情况 | 持久化结果 | 后续行为 |
|---|---|---|
| 普通、AI 仍启用的 `BOT_ACTIVE` 新消息 | 保存本条文字，并创建一个 `mini_program_processing_jobs` 后台处理任务 | RAG、AI 回复回调或业务转人工判断异步执行 |
| 历史人工用户用新 `conversationId` 发起咨询 | 保存新会话第一条文字并进入转人工流程，不创建 processing job | 创建或沿用该新会话的企微通知，不进入 RAG、不生成 AI 回复 |
| 已处于 `HANDOFF_PENDING` | 只保存本条文字，不创建 processing job | 沿用已有企微通知继续重试，不进入 RAG、不生成 AI 回复、不重复创建企微通知 |
| 使用新时间戳和新 Nonce 重试已接收的同一个 `messageId` | 不新增消息、processing job、回调或通知 | 返回第一次的 `ACCEPTED` 结果 |

上述异步工作不会在本次 HTTP 请求内完成。若会话已经是 `HUMAN_MANAGED`，新的 `messageId` 不返回 `ACCEPTED`，而是按下一节返回 `IGNORED_HANDOFF_COMPLETED`，且不保存正文。

### 4.2 已转人工会话的后续消息

HTTP `202`：

```json
{
  "ok": true,
  "accepted": true,
  "messageId": "message-demo-002",
  "status": "IGNORED_HANDOFF_COMPLETED"
}
```

此状态表示 `conversationId` 对应的企微通知已经成功，平台已永久终止该会话的本地采集和自动回复。本次正文不会保存，也不会产生 AI 回调或新的企微通知。小程序侧应继续把该用户交给自己的人工客服流程；下一次新的咨询必须使用新的 `conversationId`。

### 4.3 错误响应结构

除成功回执外，响应结构固定为：

```json
{
  "ok": false,
  "code": "<稳定机器错误码>",
  "message": "<安全的简短说明>",
  "detail": null
}
```

调用方应按 HTTP 状态和 `code` 判断，不要依赖中文 `message` 文案。

#### HTTP 400：请求体或字段无效

```json
{
  "ok": false,
  "code": "MINI_PROGRAM_PAYLOAD_INVALID",
  "message": "小程序消息格式无效",
  "detail": null
}
```

修正 JSON、UTF-8、字段集合、类型、长度或 `sentAt` 后，使用新时间戳、新 Nonce 和新签名重新请求。已经通过验签的无效载荷可能已经消耗 Nonce。

#### HTTP 401：鉴权失败或防重放拒绝

```json
{
  "ok": false,
  "code": "MINI_PROGRAM_AUTH_FAILED",
  "message": "小程序请求鉴权失败",
  "detail": null
}
```

可能的 `401` 代码包括：

| `code` | 含义 |
|---|---|
| `MINI_PROGRAM_AUTH_INVALID` | 签名请求头缺失、重复或格式不合法 |
| `MINI_PROGRAM_AUTH_FAILED` | appId 或签名不匹配 |
| `MINI_PROGRAM_TIMESTAMP_EXPIRED` | 时间戳超出允许的 300 秒窗口 |
| `MINI_PROGRAM_NONCE_REPLAY` | 10 分钟内重复使用相同 `appId + nonce` |

#### HTTP 409：会话绑定了其他用户

```json
{
  "ok": false,
  "code": "CONVERSATION_USER_MISMATCH",
  "message": "会话已绑定其他用户",
  "detail": null
}
```

不要改写用户身份后继续复用该 `conversationId`。为新的咨询生成新的 `conversationId`，并排查小程序侧会话映射。

#### HTTP 413：原始请求体超过 32 KiB

```json
{
  "ok": false,
  "code": "MINI_PROGRAM_BODY_TOO_LARGE",
  "message": "小程序请求体超过大小限制",
  "detail": null
}
```

#### HTTP 415：媒体类型、字符集或编码不支持

```json
{
  "ok": false,
  "code": "MINI_PROGRAM_JSON_CONTENT_TYPE_REQUIRED",
  "message": "小程序请求体必须使用 UTF-8 application/json",
  "detail": null
}
```

#### HTTP 503：暂时不可写

```json
{
  "ok": false,
  "code": "MINI_PROGRAM_TEMPORARILY_UNAVAILABLE",
  "message": "服务器处理失败",
  "detail": null
}
```

该响应没有声称接收成功。使用相同 `messageId`、新的时间戳、新的 Nonce 和新签名进行退避重试。

其他 `503` 代码包括 `MINI_PROGRAM_API_DISABLED`、`MINI_PROGRAM_CONFIGURATION_INCOMPLETE` 和 `MINI_PROGRAM_ACCOUNT_UNAVAILABLE`。`5xx` 的中文信息统一脱敏，运维判断应以 `code` 为准。

### 4.4 其他协议错误

| HTTP | `code` | 处理方式 |
|---|---|---|
| `400` | `MINI_PROGRAM_REQUEST_INVALID` | 检查 HTTP 请求目标、Host 和长度/传输编码，修正后使用全新签名请求头 |
| `404` | `MINI_PROGRAM_PATH_NOT_FOUND`（命中开放接口处理器时） | 检查是否使用完全一致的接口路径且没有查询参数；其他错误路径应由公网代理直接拒绝，不属于本合同接口 |
| `405` | `MINI_PROGRAM_METHOD_NOT_ALLOWED` | 改用 `POST`；响应包含 `Allow: POST` |
| `500` | `MINI_PROGRAM_INTERNAL_ERROR` | 保持 `messageId`，使用全新签名请求头退避重试；持续出现时联系平台运维 |

## 5. AI 回复回调

### 5.1 回调地址

AI 平台只调用预先通过环境变量配置的固定回调地址，入站消息不能指定或覆盖回调地址。

- 生产回调地址必须是 HTTPS。
- 仅本机联调时允许 `http://localhost`、`http://127.0.0.1` 或 `http://[::1]`。
- 地址不能包含用户名、密码、查询参数或片段。
- 回调地址的 `pathname` 是回调签名原文中的 `REQUEST_PATH`。

### 5.2 回调请求

```http
POST <固定回调路径> HTTP/1.1
Content-Type: application/json
X-Mini-App-Id: <双方约定的 appId>
X-Timestamp: <Unix 秒>
X-Nonce: <本次回调尝试的新随机值>
X-Signature: <HMAC-SHA256 小写十六进制>

{
  "eventId": "8d7ed292-8689-4ba2-901d-767a3f31df3d",
  "type": "assistant.message",
  "appId": "<双方约定的 appId>",
  "conversationId": "consultation-demo-001",
  "userId": "user-demo-001",
  "inReplyToMessageId": "message-demo-001",
  "text": "这是 AI 生成的联调回复。",
  "createdAt": "2026-09-05T09:30:02.000Z"
}
```

| 字段 | 含义 |
|---|---|
| `eventId` | 一次 AI 回复事件的稳定唯一标识 |
| `type` | 固定为 `assistant.message` |
| `appId` | 应用标识 |
| `conversationId` | 对应咨询会话 |
| `userId` | 对应小程序用户 |
| `inReplyToMessageId` | 触发本次 AI 回复的用户 `messageId` |
| `text` | 应向用户展示的 AI 文字回复 |
| `createdAt` | AI 回复事件创建时间，ISO 8601 UTC 字符串 |

回调使用与消息接口完全相同的原始字节 HMAC 算法，但签名路径改为固定回调 URL 的 `pathname`。每次发送或重试都会使用新的时间戳、Nonce 和签名；同一事件重试时 `eventId` 和业务载荷保持不变。回调接收端同样应采用不超过 300 秒的时间窗口，并在 10 分钟内拒绝重复的 `appId + nonce`。

小程序服务器必须：

1. 在解析 JSON 前保留原始请求字节并验签；
2. 校验 `appId`、时间窗口和 Nonce，签名比较使用常量时间算法；
3. 以 `eventId` 做持久化幂等，重复事件只能向用户展示一次；
4. 持久化接收成功后尽快返回任意 `2xx`，推荐 `204 No Content` 或简短的 `200`；
5. 不使用 `3xx` 跳转。平台不会跟随跳转，任何非 `2xx`、超时或网络错误都视为未送达。

平台默认回调超时为 12 秒，可配置范围为 1 至 30 秒。失败时最多自动尝试 10 次，间隔依次为 5 秒、30 秒、2 分钟、10 分钟、1 小时、6 小时、6 小时、6 小时、6 小时。因此小程序服务器必须按 `eventId` 正确处理“业务已接收但 HTTP 回执丢失”的重复回调。

当会话已经开始转人工时，尚未发送的 AI 回调会被取消。平台不会通过该回调发送人工状态、人工回复或“已转人工”消息。

## 6. 会话与转人工语义

| 状态 | 入站文字处理 | AI 回调 | 企微通知 |
|---|---|---|---|
| AI 正常处理 | 保存文字并异步处理 | 可发送 | 无 |
| 企微通知中 | 保存文字但不再进入 RAG | 不发送 | 沿用原通知重试，不重复创建 |
| 企微通知成功 | 返回 `IGNORED_HANDOFF_COMPLETED`，不保存正文 | 不发送 | 不重复通知 |

- 一个 `appId + conversationId` 首次建立后永久绑定一个 `userId`。
- 只有企微接口明确返回成功，平台才把用户标记为“曾转人工”。
- 曾转人工的 `appId + userId` 使用新的 `conversationId` 再次咨询时，平台会保存新会话第一条文字并直接通知人工，不进入 RAG，也不发送 AI 回复。
- 小程序侧负责后续人工对接和状态管理；不需要、也不应向本接口回传人工状态或人工回复。

- [ ] 代理将原始请求体字节原样转发，不压缩、解压、转码或重新序列化 JSON。
- [ ] 边缘请求体上限设为 32768 字节（32 KiB），且本地服务保持相同上限。
- [ ] 按来源 IP 和连接数设置速率限制、并发连接限制及合理突发额度。
- [ ] 设置有限的连接、读取和上游响应超时；超时值须与本地 SQLite 等待配置协调，不能无限等待。
- [ ] 监控请求量、来源 IP、HTTP 状态、稳定错误码、延迟、超时和异常突增；日志不得记录消息正文、共享密钥、完整签名或完整请求体。
- [ ] 小程序服务器按相同 `messageId`、全新时间戳/Nonce/签名实现有上限的退避重试。
- [ ] 小程序回调接收端已完成原始字节验签、`eventId` 持久化幂等和 `2xx` 回执测试。
- [ ] 本地防火墙仍限制管理服务和 RAG 服务只在受控网络内可达。

严禁通过公网反向代理暴露：

- `/api/*` 管理接口；
- `/`、后台页面或任何静态资源；
- `127.0.0.1:3100` 的整站或任意通配路径；
- RAG 服务端口 `18080`；
- Local Agent、数据库文件或其他本机端口。

## 8. 联调验收

双方至少验证以下场景：

1. 正确签名的文字返回 `202 ACCEPTED`，随后收到一次可验签的 AI 回调。
2. 相同 `messageId` 使用新时间戳和新 Nonce 重试，仍返回相同结果，AI 回调不重复创建。
3. 相同 Nonce 重放返回 `401 MINI_PROGRAM_NONCE_REPLAY`。
4. 修改原始 JSON 任一字节但沿用旧签名，返回 `401 MINI_PROGRAM_AUTH_FAILED`。
5. 无效字段、错误用户复用会话、超长正文、非 JSON 和超过 32 KiB 分别得到预期错误。
6. 回调 HTTP 回执丢失后，重复 `eventId` 不会向用户重复展示。
7. 转人工成功后，原 `conversationId` 的后续消息返回 `IGNORED_HANDOFF_COMPLETED`；新咨询改用新的 `conversationId`。
8. 公网扫描确认除精确的消息 POST 路径外，管理 API、页面、静态资源、端口 `3100` 整站和 RAG `18080` 均不可访问。
