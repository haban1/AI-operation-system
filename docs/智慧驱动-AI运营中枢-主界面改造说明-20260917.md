## 二、设计稿的三项取舍（已确认）

1. **看板指标** —— 严格按设计稿做 6 个：曝光量、新增关注、有效引流、活动报名、实际到场、入群。

## 四、实现要点

### 4.1 分组导航

- 侧边栏 `#nav` 渲染 6 个分组按钮（`data-workspace="<group>"`）。
- 顶部子导航 `#workspaceSubnav` 渲染当前分组栏目（`data-workspace-item="<key>"`），支持左右方向键 / Home / End 切换。
- **语义修正**：子导航最初沿用了设计稿的 `role="tablist"` / `role="tab"`，会与知识库页、内容创作页内部的同义 tab 冲突，导致基于角色的查询出现歧义。已改为 `nav` 地标 + 按钮，激活态用 `.active` + `aria-current="page"` 表达。

### 4.2 地址栏路由

- `navigate()` 完成后通过 `history.replaceState` 写入 `#<栏目key>`，**不产生额外历史记录**。
- 启动时按 `location.hash` 恢复页面（`resolveWorkspaceHash`），`#topics` / `#material-editing` / `#library` / `#documents` 等可直接打开。
- 监听 `hashchange`，手动改地址栏可用；因为内部用 `replaceState`，不会自激循环。
- **兼容设计稿的 `#页面名` 写法**：设计稿把 hash 直接当作 `state.page`（`#dashboard` / `#create` / `#browser` …），
  本项目主键是栏目 key。`resolveWorkspaceHash()` 先按栏目 key 匹配，再回退按页面名匹配（不区分大小写），两种写法都能落到同一页面。
  改造前 `public/app.js` **没有任何 hash 路由**（`location.hash` 出现 0 次），因此不存在旧格式兼容负担，这只是为了对齐设计稿与方便手工书签。

### 4.3 运营总览看板

- 新增接口 `GET /api/operations-dashboard?range=7d|30d&platform=<code|all>`。
- 真实统计：`publish_targets` 中 `status='PUBLISHED'` 的条数（按平台与时间窗过滤）、各平台发布量、已发布内容清单、以及基于系统真实记录（待人工、知识缺口、发布失败、登录异常、未闭环问题）生成的 AI 运营建议。
- 6 个 KPI 与转化漏斗全部为 `PENDING_SOURCE`，前端渲染「待接入」并注明所需数据源；趋势图无数据源时展示空态而非假曲线。
- 复用旧仪表盘主体为「07 · EXECUTION ENVIRONMENT / 执行环境与实时指标」（RPA 设备卡、五平台登录卡、转人工/AI 已回复/今日 AI 用量指标、安全执行原则）。
- 看板数据按 `range|platform` 缓存，切换筛选或重新进入页面时才重新请求，避免 5 秒定时刷新打接口。

### 4.4 内容创作 / 素材自动剪辑

真实可用：本地素材选择（`/pick-file`）、素材预检、AI 标题与正文生成、内容适配潜力预测、带入内容发布、作品库读取发布历史。

明确标注「待接入」：热点选题库、视频剪辑与编码、分镜配音与动效 —— 一律用 `studio-pending-card` 说明，不生成任何示例选题或占位作品。

## 五、配套测试调整

导航结构由「扁平 `data-page`」变为「分组 `data-workspace` + 栏目 `data-workspace-item`」，以下几处必须同步：

1. `test/helpers/runtime.js` 新增 `WORKSPACE_NAV`（页面 → 分组/栏目映射）、`openWorkspaceGroup()`、`openWorkspacePage()`。
   `openWorkspacePage()` 的两处实现取舍（都在源码注释里写明了原因）：
   - **用地址栏深链 `#<栏目key>` 而不是「先点分组、再点栏目」**：新导航的两次点击会产生两次 `navigate()`，对依赖渲染所有权 / 竞态的用例会改变时序；深链只产生一次导航，等价于改造前的一次点击。
   - **等待信号用「子导航高亮」而不是 `location.hash` 或 `#content` 退出 `aria-busy`**：hash 要到 `render().then()` 才写入；而有意挂起请求的用例会让 `aria-busy` 永远无法清零。子导航高亮由 `syncWorkspaceNavigation()` 在 `navigate()` 内同步完成，且必须用 `state:'attached'` —— 单栏目分组（运营总览 / 平台与账号）会隐藏整条子导航，用默认的 `visible` 会超时。
2. 5 个浏览器测试文件中的 32 处 `#nav button[data-page="X"]` 点击全部改为 `openWorkspacePage(page, 'X')`。
3. `test/mini-program-ui.test.js` 三处语义适配：
   - 导航顺序断言改为校验「用户互动」分组的栏目顺序（评论 → 私信 → 小程序对话 → 转人工记录）；
   - 两处 `#pageTitle` 断言改为「分组高亮 + 当前栏目高亮」断言（新版与设计稿一致，顶部大标题为**分组名**）。
4. `test/core.test.js` 两处资源缓存版本号由 `20260814-task-publish-time` 改为 `20260917-intellidriven-operations-workspace`（改了前端资源就必须换版本号，否则浏览器会继续用旧 app.js）。

## 六、过程中发现并修复的既有缺陷

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| **401 误判为会话过期** | 任何 401（含下游代理返回的 401）都会把运营席位强制踢回登录页。打开「知识资料」时 RAG 服务返回 `401 Bearer token无效`，运营人员会被莫名登出。改造前 `public/app.js` 同样存在此逻辑。 | `api()` 只在服务端明确返回 `code='AUTH_REQUIRED'`（管理员会话失效）时登出；`UNAUTHORIZED`（RAG）与 `AGENT_AUTH_REQUIRED`（Local Agent）只作为普通错误提示。 |
| **看板首次进入无数据** | 新看板数据只在切换筛选时拉取，首次进入显示 0 条。 | 抽出 `operationsDashboardKey`，`renderDashboard` 在筛选键变化时自动加载。 |
| **仪表盘恢复按钮文案退化** | 设计稿模板被我改写后，暂停横幅按钮文案由「启动 Agent 并恢复运行」缩成「恢复运行」，丢掉了 Local Agent 语义。 | 恢复为原文案。 |
| **两个浏览器测试硬失败** | `rag-admin-proxy.test.js` 硬编码 `C:/Program Files/Google/Chrome/...`，`rag-release-rollback.test.js` 用 `assert.ok` 直接失败；本项目其余 5 个浏览器测试都是 `skip: !chromePath` + `CHROME_EXECUTABLE_PATH`。 | 两者统一到项目既有约定：优先读 `CHROME_EXECUTABLE_PATH`，无浏览器时跳过而非失败。 |
| **「浏览器控制」整页打不开（ReferenceError）** | `renderBrowserControl()` 引用 `platformOptions`，但该变量从未在本函数内定义 —— 打开页面只显示「页面加载失败：platformOptions is not defined」。回溯 `project/WORKTREE_DIFF_20260902.patch` 可见这是一个**纯删除 hunk**（`@@ -2041,7 +2286,6 @@ async function renderBrowserControl()`）：删掉了定义行却保留了下方 `${platformOptions}` 的使用。**自 2026-09-02 起该页面一直是坏的**，与本次改造无关。 | 按被删除行的原实现恢复：`const platformOptions=selectablePlatforms.map(...)`。修复后该页渲染 1749 字符，主控未启用时给出正确的「Web Access 主控尚未启用」提示。 |
| **恢复按钮文案被改成真实中文，破坏转义断言** | 本次改造把 `data-master-resume` 的按钮文案由 `\u542f\u52a8 Agent \u5e76\u6062\u590d\u8fd0\u884c` 改成真实中文字。渲染结果完全一致，但 `smart-reply-control.test.js` 用**字面转义串**做匹配（`source.includes('\\u542f\\u52a8 Agent ...')`），会失败。 | 还原为转义形式（渲染不变），该用例恢复通过。这类「源码字面匹配」断言对本项目是一处易踩的坑，已在下方「已知限制」备注。 |

## 八、已知限制 / 待接入清单

1. **6 个 KPI 与转化漏斗无数据源** —— 需要平台曝光数据、粉丝数据、引流归因、活动报名系统、现场签到系统、社群入群数据。接口已按 `PENDING_SOURCE` 就位，接入后只需让服务端返回 `status:'READY'` 与 `value`。
2. **趋势图无数据源** —— 接入后让 `trend` 返回每日 `{label, exposure, followers, leads}` 即可。
3. **热点选题库、视频剪辑与编码、配音与动效** —— 后端不具备相应能力，页面已用「待接入」卡片说明。
4. **本机未安装 Google Chrome** —— 浏览器类测试通过 `CHROME_EXECUTABLE_PATH` 指向 Edge 运行；若要在 CI 中跑，建议安装 Chrome 或统一设置该环境变量。
5. **本机 Node 为 v22，项目要求 ≥ 24** —— `node:sqlite` 会打印 `ExperimentalWarning`，会导致个别断言 stderr 为空的用例失败。生产/CI 请使用 Node 24+。
6. **改造 `public/app.js` 时留意「源码字面量」契约测试** —— 本项目把部分中文以 `\uXXXX` 转义形式写在源码里，
   而测试用 `assert.match(appSource, /\\u5df2\\u505c\\u7528/)` 或 `source.includes('\\u542f\\u52a8 Agent ...')` 做**字面**匹配。
   把这些转义"美化"成真实中文后**渲染结果完全一致但测试会红**。本次改造在 `data-master-resume` 按钮上就踩了一次。
   反过来，若把真实中文改成转义，同样要注意模板字符串里的转义是在运行期解析的、不影响渲染。
7. **`浏览器控制` 与 `相似问法` 没有页内按钮入口** —— 改造前和改造后都只能靠地址栏进入（`问题汇总` 有 3 处按钮入口）。
   这是项目既有的产品决策（见 3.1 的说明与对应契约测试），本次未擅自改动；如需暴露入口，改法见 3.1 引用块。
8. **`hiddenNavPages` 中的 `browser-tools` 带有一个不会显示的 `hint:'高级'`** —— 该项按设计稿原文引入
   （设计稿里它是可见栏目），但被 `hiddenNavPages` 过滤后不会渲染。保留它是为了与设计稿定义保持一致，
   若将来把该项移回导航，`高级` 提示会自动出现，无需再改数据。
