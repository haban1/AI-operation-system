# 三路产物接入与人工确认入库

素材库把 AI Signal Studio、OpenChatCut 和 Toonflow 的输出汇总到同一个确认流程：**自动发现或手动接收 → 待确认 → 人工确认入库 → 可供发布选择**。同步发现、上传成功和源工作台的“选中”都不等于人工入库；确认入库也不等于发布授权。

## 两种产物入口

| 入口 | 适用情况 | 操作 |
| --- | --- | --- |
| 目录自动发现 | 来源登记、画布引用及实际媒体完整，数据目录已连接到 Web | 在素材库同步作品，从来源记录发现完成产物 |
| 手动“接收产物” | 手上已有导出文件、跨 Windows/其他电脑交接，或旧导出记录缺少路径而无法自动发现 | 在浏览器选择来源、文件、产物类型和标题，上传到素材库 |

两种入口都先进入“待确认”，随后需要独立点击“确认入库”。手动接收无需配置外部目录挂载，也无需外部应用当前保持运行；它不会启动 OpenChatCut / Toonflow 或补全来源应用的旧记录。

## 在 Windows 或其他电脑手动接收文件

1. 从来源工具完成导出，将实际文件保存到操作员电脑可读取的位置。云盘文件应先完整下载并确认可以播放或查看，不能只交接在线占位文件。
2. 登录运营系统，打开“素材库”，点击工具栏“接收产物”。
3. 选择来源“自动化成片”“素材智剪”或“AIGC 创作”，选择本地文件，按真实内容选择“最终视频”“视频片段”或“图片”，填写标题后上传。来源和类型是本次交接的标注，需要人工核对；Toonflow 的单段输出应选择“视频片段”，不能只为进入发布选择而标为最终视频。
4. 上传完成后进入“待确认”，完整预览并检查内容、来源、标题和类型。点击“确认入库”后才会出现在“已入库”；不采用则“暂不入库”。
5. 需要发布时，再从已入库作品“用于发布”或通过发布管理的“从素材库选择”带入草稿，继续原有预检、审核与最终授权。

浏览器上传会把选定文件交给 Web 保存，不要求 Windows 用户提供 Linux 容器路径。只有一个导出的 MP4、没有完整 SQLite 或画布目录时，也可使用该入口；自动发现所需的目录结构要求仍保持不变。接收成功证明文件已交接，不证明外部模型生成过程或本机两套外部服务已通过运行验证。

默认单个文件上限为 2 GiB，可由部署配置收紧；浏览器每次接收最长等待 5 分钟。大文件或跨机慢速网络可能超时，建议先导出较小文件，或由部署人员交接来源目录后使用自动发现。

## 目录自动发现：默认部署与可选挂载

`start-workbench.cmd` / `node scripts/workbench.mjs start` 默认使用 `compose.yaml` 和 `compose.signal.yaml`，启动 Web、RAG 与随仓 Signal。没有 OpenChatCut 或 Toonflow 时，无需创建任何外部来源配置。

需要读取外部产物时，在仓库根目录复制模板，已有本地配置时保留原文件：

```powershell
if (-not (Test-Path .\compose.outputs.local.yaml)) { Copy-Item .\compose.outputs.yaml .\compose.outputs.local.yaml }
notepad .\compose.outputs.local.yaml
```

启动器只自动加载 `compose.outputs.local.yaml`，不会加载模板 `compose.outputs.yaml`。`start`、`stop`、`status`、`verify` 都在原两份配置之后追加同一份本地文件，project name 仍为 `ai-operation-signal`。日志只提示是否检测到该文件，不打印配置内容或管理员凭据。本地文件不提交 Git。

模板默认包含两路外部来源。只接一路时，删除另一路的完整 volume 项和对应三条 environment 项：OpenChatCut 对应 `CONTENT_LIBRARY_EDITING_ROOT`、`VIDEO_EDITING_URL`、`VIDEO_EDITING_HEALTH_URL`；Toonflow 对应 `CONTENT_LIBRARY_CREATION_ROOT`、`AIGC_CREATION_URL`、`AIGC_CREATION_HEALTH_URL`。不需要停用随仓 Signal。

### 选择真实目录

| 来源 | 需要选择的宿主目录 | 容器内只读位置 | 发现依据 |
| --- | --- | --- | --- |
| Signal | 无需宿主目录；由随仓命名卷提供 | `/sources/ai-signal` | `runs` 中有脚本、有效视频及 `full_decode=passed`，排除源端已拒绝作品 |
| OpenChatCut | 应用当前使用的 profile 根目录，包含 `project-store-v1.sqlite3` 与 `media/uploads` | `/sources/openchatcut` | 作品登记 `generation-jobs:snapshot` 中 `succeeded` 的视频导出 |
| Toonflow | 包含各项目子目录的 workspaces 根目录；项目中有画布 JSON 和 `assets` | `/sources/toonflow` | 画布节点明确引用的已完成图片或视频输出 |

从外部应用的实际数据目录设置确认路径，不能只选一个 MP4、应用安装目录或空文件夹。OpenChatCut 挂载整个 profile 目录，SQLite、存在的 WAL/SHM 和 uploads 保持同一目录关系；**无需手工创建或单独挂载 WAL/SHM**。数据库或媒体文件暂时不存在时来源可能显示不可读取，但不会因缺少单个 WAL/SHM 绑定而阻止容器启动。

模板中的两个 `source:` 可以直接替换为本机实际绝对路径。Windows 使用加引号的正斜杠路径，例如 `"C:/WorkbenchData/openchatcut-profile"` 和 `"D:/WorkbenchData/toonflow/workspaces"`；示例目录不会自动创建，必须换成自己的真实位置。直接写在本地 YAML 中后，双击启动器也能使用。

也可保留模板中的变量，在同一 PowerShell 窗口为每次操作设置：

```powershell
$env:OPENCHATCUT_PROFILE_DIR = 'C:/WorkbenchData/openchatcut-profile'
$env:TOONFLOW_WORKSPACE_DIR = 'D:/WorkbenchData/toonflow/workspaces'
node scripts/workbench.mjs start --no-browser
```

上述两个值仅为路径格式示例。使用环境变量时，后续 `stop`、`status`、`verify` 也需在具备这些变量的终端执行；PowerShell 临时变量不会自动传给从资源管理器新双击的窗口。将路径写入本地 YAML 可避免这个差异。`.env.docker` 是容器环境文件，启动器不会把它用作 Compose 路径变量的插值来源。

模板保留 `read_only: true` 和 `create_host_path: false`。选定的 profile / workspaces 整个目录对 Web 容器只读可见，选择有权提供给运营系统的数据目录；源读取器只查询作品登记或画布引用，不扫描任意上传文件推断成片。

若已启用本地覆盖文件但缺少路径变量或目录不存在，启动器会报告配置或挂载错误，不会悄悄创建空来源。选到了存在但内容不符的目录时，挂载仍可能成功，素材库会显示来源不可读取或没有可发现产物，需要核对目录结构。修正路径后重试；暂不接外部来源时，将本地文件移出仓库根目录或改为其他文件名，再执行 `start`。已有共享库副本保留在 `web_data` 中。

### 浏览器入口、健康检查与跨机文件

模板的默认入口适用于外部应用运行在同一台 Docker Desktop 宿主机：

| 路线 | 浏览器入口 | Web 容器健康探测 |
| --- | --- | --- |
| OpenChatCut | `http://127.0.0.1:5199/` | `http://host.docker.internal:5199/` |
| Toonflow | `http://127.0.0.1:13000/` | `http://host.docker.internal:13000/` |

这些地址不会启动或安装外部应用。使用不同端口、另一台电脑或远程浏览器时，在本地 YAML 修改对应 URL，或设置 `OPENCHATCUT_BROWSER_URL`、`OPENCHATCUT_HEALTH_URL`、`TOONFLOW_BROWSER_URL`、`TOONFLOW_HEALTH_URL`。浏览器 URL 必须从操作员浏览器可达；健康 URL 必须从 Web 容器可达，外部应用本身也须允许该访问方式。远程浏览器的 `127.0.0.1` 指向浏览器所在电脑，不是服务器。

**服务 URL 可达不会传输产物文件。** 跨机使用目录自动发现时，需要把产物数据以一致快照交接到 Docker 宿主机可读取的目录，再将该宿主目录绑定到 Web。OpenChatCut 先完成导出并停止写入，通过应用支持的备份方式，或在应用关闭后复制作品数据库、存在的配套 WAL/SHM 与 `media/uploads`，保留原相对结构；不要逐个复制正在写入的 SQLite 文件。Toonflow 等待任务完成并保存画布，交接对应项目的 JSON 与 `assets`，仍按 workspaces / 项目目录组织。只复制最终 MP4 而没有来源登记，适配器不会自动发现它；此时可改用上面的“接收产物”上传该实际文件。

Windows Docker Desktop 使用可读取的 Windows 本地目录；从 WSL 运行命令时使用该环境实际可访问的路径。远端文件夹 URL、另一台电脑的盘符、未挂载的网络共享都不能直接当作宿主绝对路径。挂载成功和入口在线分开检查：外部应用暂时关闭时，已交接且有效的产物仍可能被发现。

## 确认后再供发布选择

1. 在任一来源完成生成或导出。目录自动发现要求 Signal 完整解码通过、OpenChatCut 完成视频导出并有来源登记、Toonflow 生成结束并保存画布引用；手动接收则需要实际完整的产物文件。
2. 打开“素材库”，按情况同步来源目录或点击“接收产物”上传文件。新产物先进入“待确认”，可预览；系统校验媒体并保存副本。目录中同一内容重复同步不会重复创建，内容改变后成为新的待确认版本。
3. 核对完整视频或图片、标题、正文、来源与产物类型，再选择“确认入库”或“暂不入库”。仅确认入库的作品进入“已入库”列表并可供发布选择；暂不入库的作品进入“已排除”，可点击“移回待确认”。已入库作品可通过“撤回入库确认”退回待确认。
4. 从已入库作品使用“用于发布”，或在发布管理点击“从素材库选择”。这一步仅准备素材和草稿，仍需平台选择、预检、合规审核与最终发布授权。

源端 `selected` 只表示在创作工具中选中过，独立于运营系统的人工入库确认。旧索引里没有人工确认记录的作品会进入待确认；不能把历史同步或源端选中自动当作人工批准。暂不入库或撤回入库确认不会删除源文件。旧草稿提交、定时计划创建和到点触发都会重新检查素材是否仍有有效入库确认及文件是否一致；相同字节共用一个文件，其他记录仍有效的确认可继续授权该文件。已创建并分派的发布任务不会因撤回入库而自动取消，需在发布管理单独处理。

产物类型保持来源事实：OpenChatCut 选区导出为 `video_clip`；Toonflow 图片为 `image`，视频默认是片段/预览 `video_clip`，不因为确认入库就变成完整成片。需发布完整影片时，先在剪辑工具完成组合和导出，再确认该完整输出。WebM/M4V 可以预览，当前发布预检使用 MP4/MOV，需先导出兼容格式。

入库确认接口要求管理员会话，并记录当前管理员身份：

| 接口 | 行为 |
| --- | --- |
| `GET /api/content-library` | `items` 为已入库作品，`pendingItems` / `rejectedItems` 为待确认 / 已排除队列，`counts` 分别统计 |
| `POST /api/content-library/sync`，请求体 `{}` | 发现并校验来源产物，不自动批准入库 |
| `POST /api/content-library/receive?source=editing&filename=output.mp4&artifactType=final_video&title=作品` | 用 `application/octet-stream` 上传实际文件，`source` 可选 `automatic`、`editing`、`creation`；保存为待确认，接收人取当前管理员会话 |
| `POST /api/content-library/:id/admission` | `decision` 为 `approved`、`rejected` 或 `pending`，分别确认入库、暂不入库或退回待确认 |
| `GET/HEAD /api/content-library/:id/media` | 管理员可预览待确认、已排除和已入库产物，支持 Range |
| `GET /api/content-library/:id/publish-draft` | 仅允许已入库作品准备发布草稿，并重新检查文件摘要 |

## 检查与边界

```powershell
node scripts/workbench.mjs status
node scripts/workbench.mjs verify
```

`verify` 检查随仓 Signal 的鉴权、页面/API、共享库访问和合成视频渲染，不会自动确认产物、安装外部应用、调用收费生成或发布。外部来源需额外用各一路真实输出验证“自动发现或手动接收 → 预览 → 人工确认 → 发布选择”，并检查来源版本与媒体摘要。目标 Windows / WSL2 上的挂载、外部应用与模型服务仍需在该机器实际执行验证。

已复制的库内文件位于 Web 的持久卷，源应用离线或跨机交接目录暂时不可用时仍可保留。不要使用 `docker compose down -v`。真实平台发布还需 Windows 原生 Local Agent 登录与可信文件交接；Windows 进程不能直接读取草稿中的 Linux 容器绝对路径，确认入库不会自动完成这一步。
