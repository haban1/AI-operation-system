## 在隔离环境复验

使用 Node 24+ 和本版依赖，按各模块说明准备临时数据库、临时素材及模拟账号。下表是维护时可选的入口，不代表交付时跑过全部组合。

| 验证目标 | 可运行的检查 |
| --- | --- |
| 模板注册、字段锁和入库 | 模板专篇里的五文件组合；另运行 `node --test test/montage-autosave-library.test.js`。实际编码需按引擎文档准备浏览器、FFmpeg 及自有素材。 |
| 采集窗口与提醒 | `node --test test/collection-quiet-window.test.js test/login-expiry-notification.test.js`。操作系统上的前后台表现另用独立浏览器配置验证，不碰业务账号。 |
| 预检移除、复核防重 | `node --test test/publish-without-precheck.test.js test/publish-sync-reconciliation.test.js`。用模拟平台和隔离存储，不创建真实投稿。 |
| 知识显示合同、微信桥接 | `node --test test/knowledge-conversation-api.test.js test/wechat-knowledge.test.js`。Node 模拟不能证明微信已登录或协议层实际发送成功。 |

## 运维边界

更新相应 Web、Windows Agent、Signal、RAG 或微信客户端前核对自己的挂载、授权与在途任务，先备份运行数据；静态文件更新不能替代服务端代码/镜像更新。源码回退不等于撤销已发送的消息、取消外部投稿或删除已入库作品。本次发布不是对所有平台的生产验收，也不包含任何已登录账号或机器代理配置。旧说明里的模板数量、素材预检和昵称优先显示按其日期理解。
