# 本地统一启动说明

## 目标

本项目运行在本机时，由同一个启动入口统一管理：

- AI 数字运营主服务：`http://127.0.0.1:3100`
- Local Agent：`http://127.0.0.1:17831`
- 本地 RAG 服务：`http://127.0.0.1:18080`

浏览器只需要进入主服务。主服务通过后端代理调用 RAG，浏览器不会直接接触 RAG Token。

## 一键启动

双击项目根目录的：

```text
启动本地服务.cmd
```

启动入口会按以下顺序执行：

1. 检查 RAG 是否已经运行；
2. RAG 未运行时，使用 `D:\code\rag\.venv\Scripts\python.exe` 启动 RAG；
3. 等待 RAG 健康接口可访问；
4. 启动或复用 AI 数字运营主服务；
5. 主服务自动启动 Local Agent；
6. 打开主服务管理页面。

RAG 已经运行时不会重复启动。默认只打开主管理页面，不额外打开 RAG 调试控制室；如需同时打开 RAG 控制室，可执行：

```powershell
.\start-mvp.ps1 -OpenRag
```

## 一键停止

双击：

```text
停止本地服务.cmd
```

该入口会停止由统一启动入口托管的 RAG、主服务和 Local Agent。手工启动且没有统一 PID 记录的外部 RAG 进程不会被误杀。

## 路径配置

主项目 `.env` 中通过以下配置指定 RAG 项目目录：

```dotenv
RAG_AUTO_START=true
RAG_PROJECT_ROOT=D:\code\rag
```

后期打包成一个本地程序时，可以把 `RAG_PROJECT_ROOT` 改成安装目录下的 RAG 子目录，例如：

```dotenv
RAG_PROJECT_ROOT=.\rag
```

这样主项目和 RAG 可以随程序一起分发，不依赖固定的开发机路径。

## 状态说明

RAG 健康接口返回 HTTP 200 且状态为 `NOT_READY` 时，表示服务进程已经启动，但还没有正式发布的知识库版本。上传文档、解析、测试并发布后，才会进入可用于用户问答的正式状态。
