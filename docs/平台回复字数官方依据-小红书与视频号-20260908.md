## 小红书：来源链与评论 300

项目适配器 `agent/rpa-adapters/xiaohongshu-assisted.js` 的回复路径进入通知页或私信页。这两个[官方网页](https://www.xiaohongshu.com/notification)引用[主入口脚本 index.2a842ae4.js](https://fe-static.xhscdn.com/formula-static/xhs-pc-web/public/resource/js/index.2a842ae4.js)及[bundler-runtime.ca53692f.js](https://fe-static.xhscdn.com/formula-static/xhs-pc-web/public/resource/js/bundler-runtime.ca53692f.js)。主入口将 `/notification` 路由映射到 Notification 组件，runtime 将该组件映射到下述真实资源。

直接证据：[Notification.b518404c.js](https://fe-static.xhscdn.com/formula-static/xhs-pc-web/public/resource/js/async/Notification.b518404c.js)。发送回调先检查空值／禁用状态，然后执行以下判断：

```js
if(h.value.length>300)return(0,l.zM)("评论字数最多300字"),[2];
```

该分支在 `e.onSubmit(h.value,I.value)` 之前返回，证明网页拒绝大于 300 的输入；等于 300 不会由此条件阻止。`h.value` 是评论输入字符串，计数位置在提取有效 mention 列表之前。`@昵称` 和插入的表情名称作为字符串内容参与计数；不是按肉眼看到的一个表情统一算一个。

数值 300 是直接观察到的官网前端事实；“UTF-16 单元”是依据 `.length` 的语言语义做出的确定性解释。[ECMAScript 的字符串长度规范](https://tc39.es/ecma262/multipage/text-processing.html#sec-properties-of-string-instances-length)将字符串长度定义为其中的 UTF-16 code unit 数。因此普通汉字、英文字符一般各计 1；`😀` 计 2；组合表情可能计更多。不能用 `Array.from(text).length` 替代此处的计数。

## 小红书：私信 1000

[官方私信网页](https://www.xiaohongshu.com/chat)通过同一主入口把 `/chat` 路由映射到 IM 组件；runtime 对应的真实资源是 [IM.c42fad54.js](https://fe-static.xhscdn.com/formula-static/xhs-pc-web/public/resource/js/async/IM.c42fad54.js)。

`handleEditorInput` 先取得 `getPlainText(editor)`，其结果为 `t`；输入校验的关键表达式为 `t.length>1e3`。超过时调用 `truncateEditorToLimit(e,1e3)`，并显示“消息字数限制1000字以下”。源码条件实际允许恰好 1000；不能仅按提示语中的“以下”推断为 999。

同一脚本的 `getPlainText`／`nodeToText` 将文本节点转为文本，图片表情转为 `data-emoji-name` 或 `alt`，mention 转为 `@昵称`，`br` 转为换行。输入时对这个结果调用 `.length`，因此普通文本的确定口径同样是 UTF-16；空格和换行也参与输入时计数。

`handleSend` 取得 `getPlainText(editor).trim()` 后触发发送。已观察到的上限位于输入处理阶段，不是该发送回调中的二次长度断言。官网针对文本节点截断使用 `.slice(0,n)`；对图片节点的截断处理另有路径。因此本结论适用于本项目发送的普通文本及对应 UTF-16 预检，不宣称已验证任意富文本节点组合的服务端上限。为避免自动化输入被官网静默截断，实现可在输入前用同一口径预检，并核验实际填入文本。
