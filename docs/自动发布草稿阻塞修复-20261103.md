# 自动发布草稿阻塞修复（2026-11-03）

当时已验证受影响发布任务恢复，当前状态以正式系统和平台核验为准。

## 原因与修复

1. 任务原本就配置为 AUTO，managementConfirmed=true，并不是未启用自动发布。
2. 抖音发布检查把作者编辑区与平台通知混在一起读取，正文技术词可能被误判为安全验证。改为读取编辑器外可见文本，保留真实平台验证拦截。
3. 抖音管理页排除作者标题和正文，避免将作者文字误判为审核拒绝。只依照平台明确状态纠正误报，投稿锁保留。
4. B站创作声明下拉加载存在延迟，选项可能包含空格、嵌套说明。改为限定选项范围、等待加载，并回读实际选中值。
5. B站视频管理页当前使用「已发布」标签，原识别仅接受「已通过」。现兼容两者，并限制核验只进入视频管理，拒绝图文 opus 页面。当时历史目标已正常自动核验为 PUBLISHED。
6. B站续接草稿校验要求完整文件名，但平台显示省略扩展名；标题输入框值也不在 body.innerText 中。现支持完整文件名或独立的文件名主干，并读取可见标题输入框。标题、素材、上传完成状态必须同时匹配，错误素材仍被拦截。
7. 同一任务准备中断的系统草稿可自动续接；仅精确任务指纹匹配时允许。已进入最终投稿的草稿仍只核验，不重复提交。

## 线上恢复依据

当时已重新加载执行器，并依据同一任务指纹、未提交阶段、平台列表、标题/正文/时间及素材证据纠正误报，恢复中断草稿续接和后续核验。最终投稿次数与锁继续受原防重复机制约束；已发布作品只核验，不重复投稿。原始任务、作品和截图仅保存在私有 backups/publish-auto-20261103/ 与 logs/，公开源码不包含这些业务证据。一次性恢复脚本不作为常规重试命令。
