# 微博热点浏览器采集修复

## 原因与实现

旧采集器匿名读取 `/ajax/side/hotSearch`，不使用平台浏览器登录态。本次已实测：在已登录浏览器中直接打开这个接口仍会返回 HTTP 403，但微博官方 `https://weibo.com/hot/search` 页面正常显示热榜。因此改为在现有微博浏览器会话中新建临时页，读取官方榜单的可见排名、标题及热度。

采集按浏览器会话与 `page.url()` 确认页面，严格校验 HTTPS、域名和 `/hot/search` 路径；不根据 Windows 窗口标题或地址栏识别结果定位。临时页用完关闭，不导航评论、私信和发布工作页。外部电脑操作工具的窗口 URL 识别属于工具自身能力，项目不修改其安全检查；本功能通过明确的浏览器会话和页面地址运行。

没有真实排名的置顶、推广条目和隐藏元素不计入热搜，保留原榜单排名及空缺，不补齐虚构的 50 条。每次返回实际可读的条目；登录过期、页面验证、平台暂停、繁忙或网页结构变化会显示对应原因。

## 本机连接与部署

Local Agent 增加固定只读入口 `GET /platforms/weibo/hot-topics`。Signal 使用 `X-Signal-Token` 携带从现有 Agent 密钥派生的凭据；此凭据仅能访问这个精确 GET 路径，不能调用发布、回复、关闭浏览器或其他 Agent 接口。Cookie 保留在平台浏览器，响应只返回公开榜单字段及已核验的热榜页面 URL。

从项目根目录运行：

```powershell
node scripts/configure-signal-weibo.mjs
docker compose -p tianhe-dev -f compose.yaml -f compose.wechat.yaml -f compose.workbench.yaml build signal
docker compose -p tianhe-dev -f compose.yaml -f compose.wechat.yaml -f compose.workbench.yaml up -d --no-deps --no-build signal
```

脚本把派生凭据写入已忽略的 `.env.signal`，不输出密钥；保留文件内已有模型设置。若轮换 `.env.docker` 的 Agent 密钥，需重新运行脚本并更新 Signal。Local Agent 修改后须通过原 Windows 浏览器执行端启动器重启，继续使用原有 Profile。

Signal 环境变量：`SIGNAL_WEIBO_AGENT_URL=http://host.docker.internal:17831`，`SIGNAL_WEIBO_AGENT_TOKEN` 由脚本写入；原生运行时 URL 可设 `http://127.0.0.1:17831`。网页不能输入服务地址或凭据。

平台运行开关和现有任务互斥继续生效。微博有其他任务时会提示稍后刷新；平台处于停止状态时不会自动开启平台。

## 验证

自动化覆盖受限凭据、域名欺骗、错误页面、登录跳转、403/429、验证提示、临时页释放，以及真实网页结构的 DOM 提取、广告/置顶/隐藏项过滤和原榜单排名保留。测试仅使用本机隔离网页，不发送微博内容。

2026-11-05 本机验证结果：55 项 Node 相关测试及 89 项引擎测试通过；已部署 `tianhe-signal:weibo-page-20261105`，服务健康。真实浏览器采集入口返回 HTTP 200，确认页面 URL 为 `https://weibo.com/hot/search`；随后完整刷新任务于北京时间 10:20:55 完成，微博来源状态 `ok`，19 条热搜已保存到热点选题列表，包含真实排名、热搜热度及原始来源链接，`stale=false`。热榜实时变化，每次只保存本次实际读取的条目。
