# 微博与 B 站回复字数：官方依据核查

核查日期：2026-09-08（Asia/Shanghai）。范围仅为本项目使用的网页评论回复、网页单聊纯文本私信。未进行发送测试，未读取凭据。证据为官方帮助文档及从官网 HTML、官网脚本中实际发现的公开前端资源；不将第三方整理、视频标题/简介、群资料、举报理由、客服反馈框或粉丝服务自动回复设置的上限代替消息上限。

## B 站私信：500，按 UTF-16 码元

[官方消息页](https://message.bilibili.com/) 当前 HTML 直接加载 [index.072ddb26.js](https://s1.hdslb.com/bfs/static/2233-monorepo/message-pc/static/js/index.072ddb26.js)。该资源读取返回 HTTP 200；响应 `Last-Modified` 为 `Tue, 25 Aug 2026 10:52:27 GMT`。这是一方网站部署代码证据，不是帮助文档中的长期承诺。

检查的是 `_MessageSendBox` 组件，排除了同文件中 `AutoreplyEditor` 的 `maxlength:500`。有效证据链如下：

```js
q=tk(function(){return R().length})
V=tk(function(){return q()>500})
z=tk(function(){return W()||V()})
```

`W()` 判断空文本；发送函数 `J` 首先执行 `z()||(...)`，只有未超长才触发 `window.send`。发送载荷为 `content:JSON.stringify({content:R()})`。编辑器的 `change` 事件将 `detail.raw` 写入 `R` 对应状态；界面显示 `/500`。点击发送和不带 Shift 的 Enter 均走 `J`。因此 500 并非示例值或显示阈值，而是实际发送门槛。[同一官方脚本](https://s1.hdslb.com/bfs/static/2233-monorepo/message-pc/static/js/index.072ddb26.js)

按这段代码的语言语义，普通 BMP 汉字和 ASCII 字符各计 1；例如 `😀` 由两个 UTF-16 码元组成，计 2。组合表情可能计更多。平台表情图片在编辑器中带有 `raw` 文本，所以仍按发送的原始文本计数，不能简单按画面上一个表情计 1。实现可以在 Unicode 安全边界截断，但最终预算必须按 UTF-16 码元计算。

## B 站评论：官方图文评论指南为 1000，当前网页入口计数待核验

[《评论区可以直接发图啦！》](https://www.bilibili.com/opus/752428294212681795)（编辑于 2023-01-18 18:54）的作者为“图文创作小助手”，UID `1777717548`。页面内嵌作者资料 `official.title` 为 `图文区官方账号`、`official.type` 为 `1`，因此可确认是一方官方指南。它说明图文评论的文字上限：

> 文字部分最多可输入1000字哦。

范围限制必须保留：该段介绍的是 APP 7.10.0 及以上版本的带图笔记/图文评论，文章末尾明确当时网页端不支持直接在评论区发布笔记。指南没有解释“字”的计数算法。它为保留现有评论 1000 提供相关官方依据，但不能单独证明 2026 年 `#/reply` 网页纯文本入口的服务端上限与计数算法完全一致。[官方指南](https://www.bilibili.com/opus/752428294212681795)

在上述 [官方消息脚本](https://s1.hdslb.com/bfs/static/2233-monorepo/message-pc/static/js/index.072ddb26.js) 中，`message-reply-box` 的 textarea 没有 `maxlength`；`handlePublish` 没有数字长度校验，直接将文本提交至 `/x/v2/reply/add`，评论参数含 `scene:"msg"`、`from:"im-reply"`、`plat:1`。

此入口在指定回复目标时会构造 `回复 @目标昵称 :正文` 再发送。因此，即便后续确认服务端上限，也应核对最终发送文本是否包含前缀；只给正文满额预算可能超出最终载荷预算。该观察仅描述网页逻辑，不要求本项目更换发送方式。

为补充核查，从 [官方视频页](https://www.bilibili.com/video/BV1GBXKBKEa3/) HTML 中发现 [video.06bc79dd557609860617b6c42cb6315613b53921.js](https://s1.hdslb.com/bfs/static/jinkela/video/video.06bc79dd557609860617b6c42cb6315613b53921.js)，其中引用了当前 [bili-comments.js](https://s1.hdslb.com/bfs/seed/jinkela/commentpc/bili-comments.js) 与后备 [new-comment.min.js](https://s1.hdslb.com/bfs/seed/jinkela/commentpc/new-comment.min.js)。检查这些公开组件仍未发现能够确认评论 1000 及其计数规则的发送长度校验。举报输入、昵称输入的长度限制不适用于评论。

除上述图文评论指南外，本次官方公开帮助资料检索未找到明确覆盖当前网页普通评论回复数值及计数语义的说明。没有前端校验不证明服务端没有上限；第三方 API 整理中的“1000 字符”不能升级为官方文档依据。

## 微博评论：官方文档明确 140，计数算法仍待核验

[微博客服《发布微博有字数限制吗？》](https://kefu.weibo.com/faqdetail?id=21510)（页面更新时间：2024-09-04）明确写道：

> 评论的字数上限为140字。

该条出现在正文发布、转发和评论分别说明的备注中，因此 5000 汉字的微博正文上限、500 字的转发上限都不适用于本项目评论回复。已读取完整相关段落，没有发现“两个英文算一个字”、UTF-16、Unicode 码点或 URL 折算规则。

直接匿名读取 `weibo.com/at/weibo`、`weibo.com/comment/inbox` 和 `weibo.com/` 均返回访客验证壳页，尚未取得实际评论编辑器的公开资源链接。因此不能把微博私信应用里用于群名称、群简介等字段的 `_stringBitLength` 函数自动套用到评论回复。

## 微博私信：当前官网代码不支持把 300 认定为官方上限

[官方聊天页](https://api.weibo.com/chat/) 的 HTML 直接加载 [app.d89390b2.js](https://h5.sinaimg.cn/m/pcweibochat/js/app.d89390b2.js)。读取返回 HTTP 200；响应 `Last-Modified` 为 `Tue, 08 Sep 2026 06:48:52 GMT`。

该脚本的单聊发送路径为 `send → postmsg → tocontact → newmsg`，最终路径 `/webim/2/direct_messages/new.json`。`send` 检查在线状态、空白输入及 Enter 组合键；`postmsg` 选择单聊或群聊；`tocontact` 传入原始 `text`。这一发送链没有 300 或其他数字文本上限校验，发送 textarea 也没有 `maxlength`。这只能证明没有在这些前端步骤中找到上限，不能证明服务端无限制。[官方聊天脚本](https://h5.sinaimg.cn/m/pcweibochat/js/app.d89390b2.js)

脚本确有 `_stringBitLength`，算法为 `Math.ceil((t.length+(e?e.length:0))/2)`，其中 `e=t.match(/[^\x00-\xff]/g)`。实际调用出现在群名称、群简介、群公告和加群申请理由等字段，不能作为私信正文计数证据。

已核对以下现行官方帮助页，均没有私信正文字数上限或计数规则：

- [如何使用微博私信](https://kefu.weibo.com/faqdetail?id=12700)，更新时间 2024-11-07；提供单聊入口与屏蔽设置说明。
- [微博聊天网页版相关问题](https://kefu.weibo.com/faqdetail?id=20970)，更新时间 2026-03-12；提供消息操作与转发说明。
- [私信添加的附件数量和大小有限制吗？](https://kefu.weibo.com/faqdetail?id=514)，更新时间 2026-03-09；说明附件、视频限制，不是文本长度限制。
- [微博私信/群聊记录相关问题](https://kefu.weibo.com/faqdetail?id=16298)，更新时间 2024-11-05；说明记录保存与搜索时间，不是文本长度限制。

这些客服页底部都包含 `0 / 300` 的反馈输入区。这个 300 属于“提交反馈”，不能拿来证明微博私信上限。历史私信报道、旧开放 API 文档即便出现 300，也须先核对年代和接口是否与本项目当前 `/webim/2/direct_messages/new.json` 一致。

## 证据适用边界

本次确认的是截至核查日公开部署的网页行为及官方帮助文本。网站可能灰度发布、更新资源或在服务端按账号/内容另设规则。应在共享策略中分别保存数值、计数方式、来源类型、核验日期和核验状态；数值待核实时避免在产品界面标注“官方上限”。没有通过发送测试验证服务端极限，也没有用成功发送短文本推导最大值。
