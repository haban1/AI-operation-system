# 抖音评论回复长度修复（2026-09-08）

## 问题与原因

截图中的 209 字符回复在创建发送任务前被运营后台的 120 字符检查拦截，尚未提交到抖音。正式 RAG 请求原先允许生成 600 字符，和发送端的限制不一致，因此触发了 `REPLY_PROCESSING_FAILED`。

120 是项目原先的保守配置，原 `publishedMax: 140` 也不是此次核实到的网页限制。[抖音官方回复视频评论接口文档](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/develop/server/basic-abilities/video-id-convert/video-review-data/video-comment-reply) 的 `content` 参数未明确标注字符上限；该接口与项目实际使用的网页操作入口不同。

## 官方依据

核查日期：2026-09-08。以下数字来自官网当前公开页面代码，不冒称为接口文档明文规定，也不据此推断所有 App 版本的限制。

- 评论：项目入口为抖音创作者中心。其[官方评论组件脚本](https://lf-fe-creator.douyinstatic.com/obj/douyn-creator-scm-cdn/douyin-creator-interactive/static/js/main.058a4db3.js)中，`EmojiInput` 默认 `limit = 500`；单条回复使用该组件且未覆盖限制，批量回复提交也检查 `.length > 500` 并提示“回复内容不能超过500字”。
- 私信：项目入口为 `https://www.douyin.com/user/self`。从其公开页面脚本和运行时资源表定位到[官方私信脚本](https://lf-douyin-pc-web.douyinstatic.com/obj/douyin-pc-web/ies/douyin_web/async/87108.01cb9e97.js)，发送方法在调用 `ImSdk.sendMessage` 前检查正文 `.length > 500`，超出时提示“字数超过限制”并返回。
- 两个网页入口都按 JavaScript 字符串长度校验：通常汉字、英文字母、标点各占 1，部分表情占 2 个 UTF-16 单位，组合表情还可能占更多。

## 修复行为

- 抖音评论的平台上限修正为 500。沿用项目预留 20 字符的生成策略，自动回复预算为 480；209 字符的答案可以完整通过。
- 正式 RAG 按发送目标读取同一份长度策略，避免生成预算与发送检查不一致。
- RAG 保留必要条件和步骤，无法在上限内完整回答时返回 `NO_ANSWER / ANSWER_TOO_LONG`。模型、无模型回退和评测路径均不再硬截断正文。
- 后台在创建回复任务前再校验一次。超长结果进入转人工流程，使用 `RAG_REPLY_TOO_LONG` 通知类型，说明超长原因；不生成发送任务。
- 计数对齐官网相应入口，发送正文先做 NFC 规范化，覆盖中文、表情和组合字符。

## 交付范围

运营后台修改：`src/services/platform-reply-policy.js`、`src/services/formal-rag-routing.js`、`src/server.js`。

配套 RAG 修改：`app/agent.py`、`app/pipeline.py`（开发目录为 `G:/CODE/天河AI运营/rag/rag`，安装版位于安装目录的 `rag` 子目录）。后续安装包需要同时包含这两部分。已生成的 `20260908-r3.exe` 不包含本次修复，另一台电脑上的安装程序不会因为开发目录改动而自动更新。
