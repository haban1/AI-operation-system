`compose.workbench.yaml` 的 web 服务使用 `env_file` 的 `format: raw` 加载私有配置，避免密钥中的特殊字符被插值。该文件已验证被 Git 忽略，不进入镜像构建上下文；密钥不写入浏览器代码或日志。本轮没有复制本机完整 Codex 目录、聊天历史或 OAuth 登录态。后续若更换本机密钥，需要同步此私有配置并重建 web 容器。

主程序其他业务模型继续使用原有设置。混剪会话、工程和隔离的 Codex 状态仍保存在 `/app/data/video-studio` 持久化目录。

## 修复容器 HTTPS 信任链

实际排查发现旧镜像没有 `/etc/ssl/certs/ca-certificates.crt`。Node 自带证书可以调用模型接口，但 Codex CLI 的 HTTPS 请求失败并持续重连。

Dockerfile 的运行阶段已补充 `ca-certificates`。通过正常系统信任链解决连接问题，没有关闭 TLS 证书校验，也无需额外设置网络代理。正式镜像为 `tianhe-web:f0174d9-codex-20261029`。

## 验收范围

实际 Responses 请求返回 HTTP 200；实际 Codex app-server 调用返回 `CODEX_CONNECTION_OK`。进一步通过 Codex 执行本地 FFmpeg 命令，在隔离测试目录真实生成一段 1 秒、320×240 的 H.264 测试视频，确认文件存在且非空。测试没有读取业务素材、发布内容或向 ChatCut 上传文件。

正式部署后，使用内网地址验证登录、内嵌制作页面、状态接口、模型配置和系统证书；未登录状态接口仍返回 401。对应结果位于 `backups/video-studio-config-20261029/deployed-check.json`，真实 CLI 验证日志位于同目录 `production-bridge-check.log`。
