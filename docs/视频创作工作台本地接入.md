# 三路径视频创作工作台与共享成片库

Windows 新部署请先看 [Windows 本机部署](Windows本机部署.md)。AI Signal Studio 已随仓打包，使用 `compose.signal.yaml` 即可启动；本文保留的是连接宿主机上三套已有引擎的接入方式。

内容工作台移植自本机 `platforms/workbench/dist` 的三路径 WebUI，静态文件位于 `public/video-workbench/`。主应用保留运营导航，创作区采用原工作台的三卡片、侧栏及展开布局；不再显示旧文稿分镜、自动剪辑步骤。三路引擎仍在原进程运行，切换路线或运营栏目会保留内嵌页面，退出管理端登录会销毁页面。

| 路线 | 原工作区 | 本机地址 | 入库依据 |
| --- | --- | --- | --- |
| 自动化成片 | AI Signal Studio | http://127.0.0.1:8892/ | runs 中 full_decode=passed 的视频；排除源端已拒绝作品 |
| 素材智剪 | OpenChatCut | http://127.0.0.1:5199/ | generation-jobs:snapshot 中 succeeded 的视频导出；区间导出标为片段 |
| AIGC 创作 | Toonflow | http://127.0.0.1:13000/ | 画布节点明确关联的已生成图片和视频；视频标为片段/预览 |

## 启动与配置

需要 Node.js 24+、Docker Desktop 和 Docker Compose 2.24.4+。本接入方式使用三个独立安装和启动的创作引擎；先启动 AI Signal Studio、OpenChatCut 和 Toonflow，并确认上表入口可访问。已有本机集成环境可复用仓库同级 `platforms/startWorkbench.sh` 与 `platforms/startOpenChatCut.sh`；这些启动脚本不属于本仓库。首次部署无需准备这些仓库外脚本，改用上面的随仓部署方式。

首次接入时，在运营系统仓库目录复制模板并指定真实的来源目录：

```sh
# 已有 compose.local.yaml 时保留现有配置。
cp -n compose.workbench.example.yaml compose.local.yaml
export AI_SIGNAL_HOST_DIR=/absolute/path/to/ai-video-studio
export OPENCHATCUT_PROFILE_DIR=/absolute/path/to/openchatcut-profile
export TOONFLOW_WORKSPACE_DIR=/absolute/path/to/toonflow/data/workspaces
node scripts/init-docker-dev.mjs
docker compose -f compose.yaml -f compose.local.yaml up -d --build --wait --wait-timeout 240
```

模板中的变量必须在每次运行 Compose 的终端中设置，也可在本机 `compose.local.yaml` 中替换为绝对路径。Signal 目录须包含 `runs`、`data/library-review.json`、`data/comparisons`；OpenChatCut profile 须包含作品数据库及 `media/uploads`。先启动引擎，让数据库和 WAL/SHM 文件存在，再启动运营系统；配置禁止自动创建不存在的来源目录。

macOS 若 Docker 不在 PATH，使用 `/Applications/Docker.app/Contents/Resources/bin/docker`。访问 `http://127.0.0.1:3100/#studio`；首次开发账号 `admin` / `admin123`。生成的 `.env.docker` 与本机 `compose.local.yaml` 均不提交 Git，已有配置不覆盖；仓库提供 `compose.workbench.example.yaml` 供不同机器配置。主应用只监听本机。

`AI_SIGNAL_STUDIO_URL`、`VIDEO_EDITING_URL`、`AIGC_CREATION_URL` 为浏览器入口，对应 `*_HEALTH_URL` 是服务器固定的探测地址。Docker 用 `host.docker.internal` 连接宿主，健康请求保留浏览器入口 Host，以适配 Vite 虚拟主机校验。不会放宽原引擎的 Host 允许列表。

`CONTENT_LIBRARY_SIGNAL_ROOT`、`CONTENT_LIBRARY_EDITING_ROOT`、`CONTENT_LIBRARY_CREATION_ROOT` 配置只读产物来源。Compose 仅挂载 Signal runs/审核及对比元数据，OpenChatCut 作品登记 SQLite/WAL/SHM 与 uploads，以及 Toonflow workspaces。不会扫描任意上传目录推断成片，不读取模型凭据或聊天 KV。OpenChatCut 若重启并替换 SQLite/WAL 文件，需要重新创建 web 容器刷新文件挂载：

```sh
docker compose -f compose.yaml -f compose.local.yaml up -d --force-recreate --no-deps web
```

`CONTENT_LIBRARY_DIR=/app/data/content-library` 位于持久化的 `web_data` 卷。Dockerfile 安装 Debian ffmpeg/ffprobe，弥补 npm ffprobe-static 缺失 Linux ARM64 可执行文件；发布预检沿用同一系统 fallback。停止容器不会删除库，也不会停止原引擎。不要执行 `down -v`，它会删除开发数据卷。

## 成片交接

进入共享成片库会同步本地完成输出；“同步作品”可手动刷新。当前同步由访问或手动操作触发，不是后台持续归档；OpenChatCut 导出后应及时进入成片库同步，避免源引擎清理临时产物。适配器先校验源端完成状态，再确认实际媒体轨道、大小与 SHA256，复制到内容寻址的持久化文件并原子保存索引。同一版本重复同步不会重复入库，源文件变更形成新版本。单次同步有时间/数量上限，剩余作品在后续同步继续读取。

- `GET /api/creative-workbench/status`：返回三服务公开连接状态。
- `GET /api/content-library`：返回统一索引，按短缓存自动同步。
- `POST /api/content-library/sync`：空对象触发同步；不接受任意地址或路径。
- `GET/HEAD /api/content-library/:id/media`：会话保护的预览，支持 Range。
- `GET /api/content-library/:id/publish-draft`：验证库内文件摘要，返回标题、正文、实际 materialPath 和预览地址。

上述接口均要求管理员会话。媒体源根目录、服务健康内网地址不会返回列表。库中 `selected` 只代表源工作台选择，不代表运营发布审核通过；`final_video`、`video_clip`、`image` 单独标识，Toonflow 分镜预览不会冒充完整成片。

成片库“用于发布”通过同源且检查窗口来源的消息进入原发布表单。发布管理也可点击“从成片库选择”读取同一索引。交接只填入文件、标题、正文和预览；目标平台、内容来源、预检、合规审核及最终授权仍由原流程处理，不创建发布任务。当前容器 Agent 与 Web 共用 `/app/data`；未来改为远程或 Windows Agent 时需另做可信文件暂存，不能直接使用容器绝对路径。WebM/M4V 可入库预览，当前发布预检要求 MP4/MOV，需先由创作工具导出兼容格式。

## 验证范围

本轮使用已有真实作品验证三个来源、入库去重、会话权限、媒体 Range、发布草稿路径与摘要，并在 Chrome 验证三路界面、统一库和发布选择器。未触发新的模型生成或正式发布。服务在线只证明入口可连接，不代表外部模型权限或完整生成链路通过。

源端现状：AI Signal 保留原一键创作逻辑；OpenChatCut 保留原素材剪辑/导出流程；Toonflow 已有图片和视频预览可入库，但参考图编辑、完整视频生成仍取决于其原有 provider 接入。
