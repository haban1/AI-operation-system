# 素材智剪帧预览与双语字幕

## 修复范围

1. Remotion 帧预览运行时尝试在 `/app/node_modules/.remotion` 下载浏览器，容器使用普通 `node` 用户而该目录不可写，导致 EACCES。镜像现在预装 Chromium 及中文字体，指定 `CC_BROWSER_EXECUTABLE=/usr/bin/chromium`、`CC_RENDER_GL=swangle`，并只赋予两个缓存目录写权限。继续以普通用户运行，预览无需临时下载浏览器。
2. 转写默认指向未配置的 AssemblyAI。安装并校验上游内置 Whisper Small 完整模型包（1,280,023,607 字节），切换到本地转写。音频识别在本机浏览器运行，不需要额外云端转写 Key。
3. 页面启动原本仅同步 Agent 模型，转写设置只有打开设置窗口时才同步。新增启动适配，使已保存的转写供应商、语言、模型档位及自动转写偏好在进入页面时生效，覆盖浏览器残留的 AssemblyAI 选择。

天河当前主模型是 DeepSeek，不能用它替代语音识别。字幕英文翻译继续通过天河统一模型完成，沿用天河的 Key；本地 Whisper 负责中文语音识别及时间戳。中文结果可能按短语或句子分块，不保证逐字时间精度。

本地 CPU 识别需要等待，首次加载模型比后续调用慢。剪辑完成后应校对人名、地名及专有名词。

## 部署与复现

```powershell
docker compose -f compose.yaml -f compose.wechat.yaml -f compose.workbench.yaml build openchatcut
docker compose -f compose.yaml -f compose.wechat.yaml -f compose.workbench.yaml up -d --no-deps --wait openchatcut
node scripts/setup-openchatcut-media.mjs small
# 数据库及 WAL 文件就绪后刷新天河的只读挂载。
docker compose -f compose.yaml -f compose.wechat.yaml -f compose.workbench.yaml up -d --force-recreate --no-deps --wait web
```

配置脚本通过原生 API 下载模型并核对完整性，成功后再启用本地转写；保留现有模型 Key、工程及素材，修改前备份设置到忽略提交的 `backups/openchatcut-media/`。

Docker 构建包含转写启动同步回归测试和 TypeScript／Vite 构建检查。适配代码保存在 `deploy/workbench/`，外部 OpenChatCut 源码仍保持固定版本，可重新构建复现。
