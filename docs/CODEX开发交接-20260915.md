## 7. 接手后的建议步骤

1. 打开 `project/`，先读本文件、当前 diff 和配置路径审计。确认是 main + 未提交修改；不要 reset/clean，也不要用旧工作区覆盖。
2. 执行 `git status --short --branch`、`git log -5 --oneline`、`git diff --stat`。Git 历史和源文件已恢复，通常无需重新 clone。
3. 检查新电脑目录中的 `.env` 与 `rag-service/.env`。设置 `RAG_PROJECT_ROOT=./rag-service`；核对端口、模型路径、浏览器路径和数据路径。不要在终端输出密钥值。
4. Node 使用 `runtime/node.exe` 或 Node 24 及以上（package.json 要求 >=24，本项目使用 node:sqlite）；安装 npm 后执行 `npm ci`。
5. Python 使用 3.11–3.13；在 `rag-service/` 执行 `uv sync --frozen --extra dev` 创建本机 `.venv`。也可以用已有 Python 建 venv 后安装项目和开发依赖，但应优先遵循 uv.lock。不要复制旧 venv 的绝对路径启动器。
6. 先用备份副本或隔离数据库测试。归档不迁移平台登录会话，新电脑需重新登录。首次启动前保持全局运行及各平台执行暂停。
7. 若恢复 RAG 数据，按 `RESTORE_STATE.md` 核对来源路径、重建向量索引；开发源码是 `rag-service/`，安装 EXE 的 Python 服务目录叫 `rag/`，两者不要混用。
8. 从源码根目录执行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start-mvp.ps1 -NoBrowser -WaitSeconds 45`。默认管理后台 3100，RAG 18080，以当前 .env 为准。
