# 抖音评论与私信采集修复（2026-10-29）

## 原因

抖音创作者中心把评论页迁移到了 `/creator-micro/interactive/comment`，作品选择器、评论行、空列表提示也使用了新的 DOM。旧采集器仍按旧地址和 `cmt-li-*` 结构判断，因而把已登录的评论页判断为未完成同步。Docker 开发配置还显式关闭了 `AUTO_COLLECT_ENABLED`，所以全局运行开关打开时也不会自动安排采集。

## 修改

- 评论地址校验同时支持新入口与旧入口重定向；其他页面不能当作评论页。
- 适配新作品侧栏、评论作者、时间、正文及“查看 N 条回复”控件，保留旧页面兼容。
- 从评论组件的身份字段读取稳定评论 ID；支持不透明的用户标识、带回复对象前缀的正文和单字评论。
- 按作品遍历，以已读取的作品 ID、完整标题和发布时间核对当前页面，匹配不唯一时保留不完整状态。
- 已明确显示零评论的作品直接跳过；单个作品失败时继续其他作品，并分别记录结果。
- 作品侧栏必须关闭后才读评论；选择入口暂时不可用时重新打开评论页恢复。逐作品等待不再重载整个页面，避免选中作品被重置。
- 作品发布时间若为平台已经格式化的中文文本，前端保留可读时间，避免显示 `Invalid Date`。
- 在 `compose.workbench.yaml` 打开自动采集，沿用平台运行状态、已启用账号和现有随机间隔调度。当前为每 4～5 分钟检查一次；已有采集任务时会跳过重复排队。

## 使用

打开 `http://127.0.0.1:3100/#comments`，选择“抖音 · 港澳社区-抖音”，查看按作品分组的评论；点击顶部“私信”或打开 `#private-messages` 查看私信记录。部署后刷新已有页面，取得新的自动采集配置。

私信沿用未读会话采集规则，当前主要为“分享[视频]”预览。多条未读会话的预览保留人工处理状态，完整会话正文仍需进一步读取。抖音智能回复本次保持关闭，仅采集和展示数据，不会自动发送回复。
