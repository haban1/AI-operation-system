## 修复了什么

修改前，`NO_ANSWER`、`NEED_CLARIFICATION`、`REJECTED` 在私信里汇入相同的澄清路径。
这会将“系统没有找到足够依据”解释成“用户没说清楚”，可能利用不可靠候选生成确认题，
再累计到三轮转人工。宽泛政策问题也可能在真正检索前被要求补对象。

现在，有主题的宽泛问题进入 RAG；确实缺少业务对象的提问仍保留有界澄清。证据不足
最多检索两轮，仍不足则私信返回 `RAG_KNOWLEDGE_GAP`，不增加澄清次数，也不自动改变
为人工接管。用户可以主动请求人工。评论无可靠答案、风险、已人工会话和服务故障继续
走原有业务规则。

生成前只构建一次当前轮的最终证据：单跳 floor 后最多 4，多跳全保留最多 6。
Gate、生成和工具可读范围完全一致。答案实际引用是有效子集，未知引用直接拒答。
重试只在原有发布/测试 scope 内合并去重；不读取其他知识库或未发布资料。

## 关键回归

- 单跳限制、低分尾部过滤、Top 1 兜底；多跳第 5/6 条和第 5 位第二来源完整保留。
- 联合 query coverage、灰区分类接收完整证据、渠道最低阈值不能被模型放宽。
- 两轮预算、最多四条第二轮查询、跨轮候选去重与原范围复核；第二轮不足继续拒答。
- Gate/生成 IDs 一致、有效引用子集、非法引用拒绝；模型工具不能再检索新证据。
- 原始问题与搜索改写分离，搜索失败不添加用户未问的价格、报名、实时开课要求。
- profile 严格字段校验、知识库隔离、重开数据库持久化、请求开始的不可变快照。
- 人设只进入生成，Trace 不记录完整自定义风格；前端保存、取消、失败保留输入和转义。
- 管理员认证、固定运营知识库、会话过期结果、人工接管、发布回滚与小程序回调幂等。

主要入口：`rag-service/tests/test_evidence_workflow.py`、`test_answer_profile.py`；
`test/formal-rag-routing.test.js`、`rag-formal-routing-integration.test.js`、

## 真实模型小样本

在隔离临时 SQLite/Qdrant 目录中，上传两份合成 CSV，共五条 FAQ；经过原有测试与发布
流程后查询。为避免下载额外大模型，检索使用明确标记的 hash embedding 与 lexical
reranker 测试提供器；生成使用官方 DeepSeek，实际运行框架为 Deep Agents + LangGraph。
未将本机密钥或真实公司文档加入仓库。

| 问题 | 结果 | 观察 |
|---|---|---|
| 测试服务如何注册？ | ANSWERED | 按资料给手机号验证注册步骤，测试会话路径 |
| 测试服务能做什么？ | ANSWERED，一轮，2.75 秒 | 直接说明课程笔记与资料查询；四个审核/生成候选，两个实际引用 |
| 测试服务的具体收费是多少钱？ | NO_ANSWER，两轮，2.94 秒 | 资料无价格，不编造，也不要求用户先提供偏好 |

调试查询中的未通过候选是 `DEBUG_CANDIDATE`，不是答案引用；正式 `NO_ANSWER` 不向用户
提供已验证答案引用。小样本延迟受模型、网络和测试提供器影响，不能替代 BGE/Qdrant
在真实知识库上的性能对比。

## 部署资料隔离

根 Docker context 使用 deny-all 加显式运行目录允许清单，`rag-service` 的 Dockerfile
也只复制 app/static/scripts/eval；两个 Compose 都不挂载开发记录。Windows 安装器按
明确目录/文件复制，Node 包是 private，没有整库发布或生产 `git pull` 链路。

新增 `dev-notes` / `AGENTS.md` 的 Git `export-ignore`。以相同暂存对象和根 attributes
构建的精简交付归档共56个成员，确认开发资料被排除；为避免下载无关媒体，没有验证
整库媒体归档。Docker 和 Windows 路径本次为配置审查，没有重建正式镜像或安装包。

后续在运营实际部署更新后，应选择原发布版本进行一轮真实语料验收，分别观察不必要的
回问率、无证据拒答、错误作答、必要人工接管和回答延迟。不要以降低所有门槛代替该验证。
