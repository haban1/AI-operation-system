# 统一模型配置

在天河「系统设置 → 企微及 AI → AI 服务配置」维护在线模式、接口地址、API Key、对话模型和视觉模型。保存后，后续调用使用新值，无需分别修改机器人。

| 使用方 | 配置来源 |
| --- | --- |
| 天河 Web、Local Agent | 主程序模型配置 |
| 天河知识库答案生成、查询改写、Deep Agent | 主程序对话模型 |
| 8080 微信原生 Agent、群总结 | 主程序对话模型，经 tianhe-robot-chat 等内部别名调用 |
| 微信识图 | 主程序视觉模型 |
| 微信原生知识库向量化 | 主程序 embeddingModel，当前为 local:BAAI/bge-small-zh-v1.5（512 维） |

8000 微信客服 Agent 已退役。微信的知识存储、分块、检索及回复策略使用 8080 原生逻辑，详见 [微信原生客服说明](微信原生客服迁移-20261019.md)。天河其他渠道的知识库索引和本地重排继续保留。

内部接口为 `/api/model/v1/chat/completions` 和 `/api/model/v1/embeddings`，由专用 `TIANHE_MODEL_TOKEN` 鉴权，只接受预定义用途别名。上游密钥仅保存在天河，机器人保留内部连接凭据。机器人应使用 `http://tianhe-model-gateway:3100/api/model/v1`，不要改回旧 8000 地址。

微信向量模型配置为 `local:BAAI/bge-small-zh-v1.5` 时，网关调用现有 RAG 服务里的本地向量模型，不调用 DeepSeek 向量接口。机器人设置中保持 `text_embedding_model=tianhe-robot-embedding`、`text_embedding_dimension=512`。换向量模型或维度后必须重建索引。

天河处于模拟模式或未配置有效密钥时，统一模型接口返回不可用，请先启用在线模式并配置有效密钥。机器人原生绘图、语音插件的独立配置不由聊天模型网关接管。视觉模型需要填写真正支持图片输入的模型。

模型调用结果与错误可在天河 AI 调用日志查看。流式调用记录结果和耗时，当前不汇总流中的 Token 用量。

当前部署日常启动：

```powershell
docker compose -f compose.yaml -f compose.wechat.yaml up -d --build --wait --wait-timeout 240
docker compose --env-file .env.robot-native -f compose.robot.yaml up -d
docker exec wechat-nginx nginx -s reload
```

`.env.docker` 和机器人原生设置已完成内部网关绑定，`.env.robot-*` 保存当前机器人部署信息。不要运行历史 8000 初始化/绑定脚本来覆盖当前配置。
