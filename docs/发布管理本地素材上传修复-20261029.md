# 发布管理本地素材上传修复（2026-10-29）

容器部署中的 Local Agent 运行在 Linux。原“选择本地素材”调用 Agent 的 Windows 原生文件对话框，因此返回“仅支持 Windows”。即使手工填写浏览器电脑的 Windows 路径，容器也不能直接读取该路径。

发布页现在通过浏览器文件选择器选择图片或视频，再将文件流上传到 Agent 所在设备。上传完成后自动填写可读取的素材路径，沿用原有预览、格式预检、平台适配、AI 文案和审核流程。浏览器上传不会创建发布任务，也不会自动授权最终发布。

支持 JPG/JPEG、PNG、WEBP、MP4、MOV。默认单文件上限 2 GiB，由 `MATERIAL_UPLOAD_MAX_BYTES` 调整，最大 20 GiB。上传文件默认放在数据库目录下的 `publish-materials`，可由 `MATERIAL_UPLOAD_DIR` 指定。当前容器目录为 `/app/data/publish-materials`，随原有 `web_data` 卷持久化，重建容器不会丢失；每次上传使用独立目录，同名文件不会覆盖。

上传接口为 `POST /api/local-agent/upload-material?filename=...`，使用 `application/octet-stream` 和文件长度。Web 检查管理员登录、来源、运行开关及 Agent 绑定，再流式转发；Agent 校验共享 Token、文件名、大小、真实媒体格式。文件不经过 JSON 请求体缓冲，失败或中断会清理该次未完成文件。已有设备路径的手动输入和旧原生接口仍保留。

修改文件：`public/app.js`、`public/index.html`、`src/config.js`、`src/server.js`、`src/services/material-upload.js`、`agent/local-agent.js`、`test/material-upload.test.js`、`package.json`、`compose.workbench.yaml`。

验证：15 项测试通过（真实 Web/Agent 上传链路、原 Agent 代理和认证测试）；覆盖中文文件名、超过 JSON 上限、并发同名上传、图片/视频预检、Range 预览、未授权访问、非法路径、空文件、超限文件、伪造媒体及中断清理。浏览器在隔离环境实际选择 PNG 和 MP4 成功，图片预览正常，视频加载为 320×240，且能继续执行 B 站平台适配检测。测试使用模拟素材和隔离数据，没有发布内容。

部署镜像为 `tianhe-web:f0174d9-upload-20261029`，使用原有 Compose 配置仅更新 web；微信容器保持运行。修改前源码、Compose 配置、测试日志和构建日志保存于 `backups/material-upload-fix-20261029/`。部署后的实际上传验收写入同目录 `production-smoke.json`。
